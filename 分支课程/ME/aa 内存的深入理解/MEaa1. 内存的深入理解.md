## 1. 进程、线程、程序

### 1.1 程序 Program

**程序**是存储在磁盘上（而非内存中）的**静态文件**，包含机器指令和数据。也就是链接器的最终产物。

| 特征           | 说明                                        |
| ------------ | ----------------------------------------- |
| **存在形式**     | 磁盘上的可执行文件（如 `.exe`、`a.out`、`.elf`）        |
| **内容**       | 机器指令（`.text`）+ 数据（`.data`、`.rodata`）+ 元信息 |
| **生命周期**     | 永久存在（直到被删除）                               |
| **是否占用 CPU** | ❌ 不占用，只是一堆字节                              |
| **类比**       | 一本**菜谱**（写满了步骤，但没人执行）                     |

程序本身是**静态的**，不会主动运行。只有当它被加载到内存中并开始执行时，才会变成进程。

### 1.2 进程 Process

**进程**是程序的一次**运行实例**，是操作系统（OS）进行**资源分配**的基本单位。

具体来说，当我们双击一个可执行文件（比如 `.exe`）时，内存中就出现了这个程序的实例——进程。

| 特征           | 说明                                                 |
| ------------ | -------------------------------------------------- |
| **存在形式**     | 运行在内存中的**实体**                                      |
| **包含内容**     | 代码段、数据段、堆、栈、文件描述符、寄存器状态、程序计数器（PC，Program Counter）等 |
| **生命周期**     | 从程序加载到内存开始，到程序结束退出为止                               |
| **是否占用 CPU** | ✅ 占用（被调度执行）                                        |
| **类比**       | 按照**菜谱**（程序）进行的一次**实际烹饪过程**（进程）                    |

**关键点**：

- **一个程序可以对应多个进程**（比如你同时打开两个浏览器窗口，每个窗口是一个进程）。
- **每个进程拥有独立的虚拟地址空间**（这将在稍后学习到）。

### 1.3 线程 Thread

**线程**是进程内部的**执行单元**，是操作系统进行 **CPU 调度**的最小单位。

具体来说，一个线程的机器指令可以同时被多个线程共享和执行。

一个 CPU 通常有多个**内核**（比如 16 个），一个内核通常有多个**逻辑处理器**（比如 2 个），一个逻辑处理器通常一瞬间**只能同时有一个**线程被执行。

| 特征       | 说明                                                       |
| -------- | -------------------------------------------------------- |
| **存在形式** | 依附于进程存在，不能独立存在                                           |
| **包含内容** | 自己的栈、寄存器状态、程序计数器（PC）                                     |
| **共享资源** | 与同进程的其他线程**共享**代码段、数据段、堆、文件描述符等                          |
| **生命周期** | 由进程创建，随进程结束而结束                                           |
| **类比**   | 一个厨房里**多名厨师**（线程）共用同一本菜谱和同一批食材，各自独立完成一部分烹饪任务，以完成同一道菜（进程） |

## 2. 物理内存 Physical Memory

### 2.1 物理内存的基本概念

**物理内存**是指计算机中实际存在的硬件内存，也就是我们常说的 RAM（Random Access Memory，随机存取存储器）。它是 CPU 能够通过内存总线直接访问的存储空间。

|特征|说明|
|---|---|
|**本质**|硬件设备（内存条）|
|**容量**|由硬件决定，如 8GB、16GB、32GB|
|**访问方式**|CPU 通过**物理地址**（Physical Address）直接访问|
|**特点**|断电后数据丢失（易失性）|
|**管理方式**|由操作系统内核统一管理|

在早期的计算机系统中（如 DOS 时代），程序直接操作物理地址。程序员需要知道内存条的具体大小和布局，才能正确编写程序。

## 2.2 直接使用物理内存导致的问题

如果程序直接操作物理地址，会引发以下严重问题：

![[物理内存.png]]

> **提示**：**OS** 即**操作系统** Operating System 。

### 问题一：内存空间不足

- 程序的大小受限于物理内存的总量。如果机器只有 4GB 内存，就无法运行一个需要 8GB 的程序。
- 多个程序同时运行时，它们需要瓜分有限的物理内存，导致系统资源紧张。

### 问题二：地址冲突

- 两个程序如果同时写入同一个物理地址，会互相覆盖数据，导致程序崩溃。
- 更严重的是，一个程序可能意外地篡改操作系统内核所在的内存区域，导致整个系统崩溃（蓝屏/死机）。

```cpp
// 假设两个程序都尝试写入物理地址 0x1000
// 程序 A
*(int*)0x1000 = 42;
// 程序 B
*(int*)0x1000 = 100; // 覆盖了程序 A 的数据
```

### 问题三：程序加载位置固定

- 程序必须被加载到指定的物理地址才能运行。如果该地址已被其他程序占用，程序就无法运行。
- 这严重限制了程序的灵活性和多任务处理能力。

### 问题四：安全风险

- 恶意程序可以扫描或修改其他程序乃至操作系统的内存数据，造成严重的安全漏洞。
- 没有隔离机制，程序之间可以随意窥探彼此的内存。

**这些问题催生了“逻辑内存”的诞生。**

## 3. 虚拟内存 Virtual Memory

### 3.1 虚拟内存的基本概念

**虚拟内存**（Virtual Memory）是操作系统在物理内存之上抽象出的一层“假想内存”。它为每个进程提供了**独立的、连续的、私有的**虚拟地址空间（Virtual Address Space）。

> [!TIP] **提示**：逻辑内存和虚拟内存
>  你可能听说过**逻辑内存**（Logical Memory），它在某些教材和操作系统中与“虚拟内存”混用，但在更严格的计算机体系结构术语中，**逻辑地址**（Logical Address）和**虚拟地址**（Virtual Address）有细微差别。
>  
>  **但在此教程中，我们统一将操作系统为每个进程提供的独立地址空间称为“虚拟内存”，将 CPU 发出的地址称为“虚拟地址（Visual Address, VA）”**。

| 特征       | 说明                                                        |
| :------- | :-------------------------------------------------------- |
| **本质**   | 操作系统在物理内存之上抽象出的一层“假想内存”                                   |
| **容量**   | 由 CPU 位宽决定（32 位系统为 4GB，64 位系统为 2^64 字节 ≈ 16.8 百万 TB）      |
| **访问方式** | CPU 通过**虚拟地址**（VA）访问，由 MMU（Memory Management Unit）转换为物理地址 |
| **特点**   | 每个进程拥有独立的虚拟地址空间，互不干扰                                      |
| **管理方式** | 由操作系统（OS） + MMU 共同管理                                      |

简单来说：**虚拟内存让每个进程都以为自己独占了整台计算机的内存。**

![[虚拟地址.png]]

虽然两个进程的虚拟地址空间都是从 `0x0000` 到 `0xFFFF`，但它们各自独立，互不影响。

![[虚拟内存到物理内存的直接映射.png]]

从图中我们能发现：

1. 每个进程都拥有一个独立的虚拟内存，一个进程的所有线程共享这个虚拟内存。
2. 虚拟内存的多个部分会被 OS 分配到物理内存（或者磁盘）的多个部分。
3. 虚拟内存中的连续的数据在物理内存中可能是离散（碎片化）的。
4. OS 也会把部分虚拟内存映射到磁盘上，磁盘的读写速度远比 RAM 慢，这降低了进程的运行速度，但也解决了内存不足的问题，是一种以时间换空间的解决方式。

> [!NOTE] **概念**：换入换出 Swap In / Swap Out
> **换入换出**是操作系统实现“虚拟内存大于物理内存”的核心机制。操作系统（OS）会在磁盘上建立**交换区（Swap Space）**，将暂时不用的数据从物理内存搬到交换区上，腾出空间给当前需要运行的进程。
> 
> |方向|名称|说明|
|---|---|---|
|**内存 → 磁盘**|**换出（Swap Out）**|将物理内存中暂时不用的页写入磁盘，释放物理页框|
|**磁盘 → 内存**|**换入（Swap In）**|将磁盘中暂存的页加载到物理内存，恢复访问|

现在你能发现，当我们执行 `std::cout << &val` 时，输出的地址实际上是虚拟内存的地址。虚拟内存是仅当前进程所占有的，OS 也能保证不同虚拟内存映射到的物理内存不会相互冲突，这也解释了为什么即使我们的进程乱操作内存也不会影响其他进程。

> [!NOTE] **概念**：进程隔离 Process Isolation
> **进程隔离**是操作系统的一项核心安全与稳定性机制：**确保每个进程只能访问自己的虚拟地址空间，无法干涉其他进程（包括 OS 内核）的内存。**进程隔离的实现依赖：
> 
> |依赖层级|组件|在进程隔离中的角色|
|---|---|---|
|**硬件**|**MMU**|强制地址转换，没有它进程隔离无法硬件化|
|**硬件**|**CR3 寄存器**|存储当前进程的页表基址，切换进程即切换地址空间|
|**硬件**|**页表权限位**|U/S 位隔离用户/内核，R/W/NX 位约束进程自身行为|
|**OS**|**独立页表**|每个进程一张页表，只映射自己的物理页框|
|**OS**|**PCB + 上下文切换**|保存/恢复进程的 CPU 状态（含 CR3），完成地址空间切换|
|**OS**|**异常处理程序**|缺页中断处理换入，页保护异常拦截非法访问（U/S 或 R/W/NX 违规），发送 SIGSEGV|
> 
> 如果你看不懂这张表也没关系，继续本系列学习即可，接下来会逐一讲解到。

### 3.2 直接使用虚拟内存导致的问题

虚拟内存虽然解决了物理内存的诸多问题，但直接使用它仍然面临挑战：

我们已经知道了虚拟内存和物理内存间存在着映射关系，要处理映射，必然需要一张映射表来记录虚拟地址（VA）到物理地址（Physical Address, PA）的对应关系，比如：

|   VA   |   PA   |
| :----: | :----: |
| 0x0000 | 0x0000 |
| 0x0001 | 0x0001 |
| 0x0002 | 0x0002 |
|  ...   |  ...   |
| 0xFFFF | 0xFFFF |

让我们简单做个计算：

对于 32 位系统，一个虚拟内存的地址范围为 `0x00000000 - 0xFFFFFFFF`（共 4GB 地址空间）。十六进制中，每位有 16 个状态，而每个地址有 8 位，因此若采用“逐字节映射”（每个字节独立映射），映射表的行数为：
$$
16^8 = 4,294,967,296 \text{（行）}
$$
映射表中每行需要存储一对地址——虚拟地址（VA），物理地址（PA）。我们用行的序数代表 VA，则实际只需要存储 PA，每个 PA 占用 4 字节。一张完整的逐字节映射表大小为：
$$
4,294,967,296 \times 4 = 17,179,869,184 \text{ B} = 16 \text{ GB}
$$
如果计算机中有 200 个进程，则所有映射表占用的总大小约为：
$$
16 \times 200 = 3,200 \text{ GB}
$$
这显然是**不可接受的**——光是页表就要占用比物理内存大得多的空间。
同理，对于 64 位系统，地址空间更大，一张逐字节映射表的大小更是天文数字，完全不现实。

为了解决这个问题，我们就需要**分页（Paging）**机制。

## 4. 分页 Paging

**分页（Paging）** 是操作系统实现虚拟内存的核心机制。它的核心思想是：**将虚拟地址空间和物理内存都划分为固定大小的块，然后建立两者之间的映射关系**。

|   概念   |       英文       |   所属区域   | 说明                         |     |
| :----: | :------------: | :------: | -------------------------- | --- |
| **页**  |    **Page**    | **虚拟内存** | 虚拟地址空间中的固定大小块，通常为 4KB      |     |
| **页框** | **Page Frame** | **物理内存** | 物理内存中的固定大小块，大小与页相同         |     |
| **页表** | **Page Table** |    -     | 记录“哪个虚拟页 → 哪个物理页框”的映射关系及权限 |     |

### 4.1 页 Page

**页**是虚拟地址空间被划分成的**固定大小块**，是分页机制中虚拟内存一侧的基本单位。

|特征|说明|
|---|---|
|**大小**|由硬件决定，通常为 4KB（x86/x64 默认），也支持 2MB 或 1GB 大页（Huge Page）|
|**对齐**|页的起始地址必须是页大小的整数倍|
|**数量**|由虚拟地址空间大小 / 页大小决定（32 位 4GB 空间有约 100 万个页）|
|**作用**|将进程的虚拟地址空间划分为可独立管理的单元|

### 4.2 页框 Page Frame

**页框**是物理内存被划分成的**固定大小块**，是分页机制中物理内存一侧的基本单位。

| 特征     | 说明                                  |
| ------ | ----------------------------------- |
| **大小** | 与页大小相同（通常 4KB），确保一一对应               |
| **对齐** | 页框的起始地址必须是页框大小的整数倍                  |
| **数量** | 由物理内存大小 / 页框大小决定（4GB 内存约有 100 万个页框） |
| **作用** | 物理内存的分配单元，存放被映射过来的虚拟页内容             |

![[虚拟内存到物理内存的分页映射.png]]

### 4.3 页表 Page Table

**页表**是操作系统为每个进程维护的一张**映射表**，记录了每个页被映射到哪个页框，以及该页的**访问权限**和**状态**。

|    特征    | 说明                       |
| :------: | ------------------------ |
|  **归属**  | 每个进程一张独立的页表              |
| **存储位置** | OS 自身的物理内存中（由 OS 分配和管理）  |
|  **作用**  | 将虚拟地址翻译成物理地址，控制内存访问权限    |

通常一个页表有以下列（也叫字段、标志位）：

| 分类       | 字段                         | 说明                          |
| -------- | -------------------------- | --------------------------- |
| **映射地址** | VPN（Visual Page Number）    | 页表的索引                       |
| **映射地址** | PFN（Physical Frame Number） | 物理页框号（转换结果）                 |
| **权限位**  | Present / Valid            | 该页是否**在内存中**（支持缺页）          |
| **权限位**  | R/W（Writeable）             | 该 PA 是**只读**还是**可读写**（保护数据） |
| **权限位**  | U/S                        | **用户态**还是**内核态**（隔离系统/用户）   |
| **权限位**  | NX / XD（Execute Disable）   | 是否**可执行**（安全防注入）            |
| **状态位**  | Accessed                   | 最近是否**被访问**（页面置换算法用）        |
| **状态位**  | Dirty                      | 是否**被修改**（换出时是否要写回磁盘）       |

表中的每一个存数据的行叫做**页表项（Page Table Entry, PTE）**，例如：

| **虚拟页号 (VPN)** | **物理页框号 (PFN)** | **存在位 (P)** | **读/写位 (R/W)** | **用户/系统位 (U/S)** | **执行位 (NX)** | **访问位 (A)** | **脏位 (D)** | **下一级页表地址 (仅多级页表)** |
| -------------- | --------------- | ----------- | -------------- | ---------------- | ------------ | ----------- | ---------- | ------------------- |
| `0x000A`       | `0xF007`        | `1`         | `1`            | `0`              | `0`          | `1`         | `0`        | `0x0000`（无）         |
| `0x7E00`       | `0x032A`        | `1`         | `1`            | `1`              | `1`          | `0`         | `1`        | `0x0000`（无）         |
| `0x009C`       | `0x0000`        | `0`         | `0`            | `0`              | `1`          | `0`         | `0`        | `0x0000`（无）         |

当进程需要访问自己的物理内存时，CPU 会先获取到进程给出的 VPN（也就是我们在 C++ 中看到的地址），然后 CPU 会查找这个进程的页表，如果找到匹配的 PTE，并且确认权限合法，才会真正访问物理内存。

> [!NOTE] **概念**：用户态和内核态
> **用户态（User Mode）** 和 **内核态（Kernel Mode）** 是 CPU 的两种**特权级（Privilege Level）** 状态，用于控制代码能够执行哪些指令、访问哪些内存区域。它们是操作系统实现**安全隔离**和**权限控制**的硬件基础。
> 
> 在 x86 架构中，特权级分为 0~3 共 4 个级别（Ring 0 ~ Ring 3）。**Linux 和 Windows 只使用其中的两个**：**Ring 0（内核态）** 和 **Ring 3（用户态）**。
> 
> 用户态：
> 
> |特征|说明|
> |---|---|
> |**权限**|只能执行**非特权指令**（如普通算术运算、内存读写）|
> |**内存访问**|只能访问**用户空间**的虚拟地址（`U/S=1` 的页），无法访问内核空间（`U/S=0`）|
> |**硬件访问**|不能直接访问硬件设备（如磁盘、网卡、显卡）|
> |**敏感指令**|不能执行修改 CPU 状态、控制中断、切换页表等特权指令（如 `lgdt`、`cli`、`hlt`）|
> |**崩溃影响**|用户态程序崩溃通常只影响自身进程，不会导致整个系统崩溃|
> 
> 内核态：
> 
> |特征|说明|
> |---|---|
> |**权限**|可以执行**所有指令**（包括特权指令）|
> |**内存访问**|可以访问**整个虚拟地址空间**（用户空间 + 内核空间）|
> |**硬件访问**|可以直接访问硬件设备（通过 MMIO 或 I/O 端口）|
> |**敏感指令**|可以执行任何指令，包括修改 CPU 状态、控制中断、切换页表（如 `mov cr3`）|
> |**崩溃影响**|内核态代码崩溃通常导致**整个系统崩溃**（蓝屏 / Kernel Panic）|

## 5. 页表权限位与段的联系

理解页表中的“**权限位**”是理解“**段（Segment）**”这个概念的关键，若不了解权限位请回顾上一章节 [[#4.3 页表（Page Table）]] 中页表字段表中的权限位。

| 页表权限位              | 对应的段                | 说明         |
| :----------------- | :------------------ | :--------- |
| `R-X`（只读/不可写/可执行）  | **代码段（.text）**      | 代码区，只读且可执行 |
| `R--`（只读/不可写/不可执行） | **只读数据段（.rodata）**  | 常量区，只读     |
| `RW-`（可读/可写/不可执行）  | **数据段（.data/.bss）** | 全局/静态区     |
| `RW-`（可读/可写/不可执行）  | **堆（Heap）**         | 动态分配内存     |
| `RW-`（可读/可写/不可执行）  | **栈（Stack）**        | 函数调用与局部变量  |

**核心思想**：“**段**”是 OS 对一组**连续**且拥有**相同页表权限位**的页的**逻辑模型**。

当一组连续的页具有相同的权限位（如 `R-X`），它们在逻辑上就构成一个“段”（如代码段）。页表权限位不同，就是不同的段。例如：

| 段         | 虚拟地址范围（示例）                      |
| --------- | ------------------------------- |
| `.text`   | `0x400000` ~ `0x4FFFFF`         |
| `.rodata` | `0x500000` ~ `0x50FFFF`         |
| `.data`   | `0x600000` ~ `0x60FFFF`         |
| 堆         | `0x610000` ~ `0x7FFFFFFF`（动态）   |
| 栈         | `0x7FFFFFFF` ~ `0x7FFFE000`（向下） |

特点：

1. 这些段都在虚拟内存中唯一存在（比如不会在数据段前后出现两个代码段）
2. 段内的地址是连续的（比如不会“段首 ~ 0A, 0C, 0E ~ 段位”）

> [!NOTE] **概念**：高位地址与低位地址
> 在计算机内存中，**高位地址**和**低位地址**是用来描述数值大小的相对概念，而不是固定的数值。它们在内存布局、栈的增长方向、地址空间随机化（ASLR）等场景中频繁出现。
> 
> |术语|含义|示例|
> |---|---|---|
> |**低位地址（Low Address）**|数值较小的地址，靠近 `0x00000000` | `0x00001000` |
> |**高位地址（High Address）**|数值较大的地址，靠近地址空间的上限| `0xFFFF0000` |

> [!TIP] **提示**：虚拟内存中的布局
> 在典型的进程虚拟内存中，不同段被放置在不同高度的地址上：
> 
> |段|典型位置（32 位 Linux）|地址范围|
> |---|---|---|
> |**代码段（.text）**|低位地址| `0x08048000` 附近|
> |**只读数据段（.rodata）**|低位地址|紧跟在 `.text` 后面|
> |**数据段（.data/.bss）**|低位地址|紧跟在 `.rodata` 后面|
> |**堆（Heap）**|中低位 → 中高位|从低地址向高地址**增长**|
> |**栈（Stack）**|高位地址|从高地址向低地址**增长**|
> |**内核空间**|最高位地址|32 位系统：`0xC0000000` 以上|
> 
> ![[虚拟内存中段的布局.png]]
> 
> **保留区（Reserved Region）**是虚拟地址空间中一段既不映射物理内存，也不属于任何段的地址范围，它在 PTE 中的 Present 位为 0。它的作用包括占位、供未来使用、对齐等（段也需要内存对齐），也就是说保留区可以出现在段中的任何位置。
> 
> 最低位的保留区是一直特别的保留区，它也叫作“**空指针陷阱区（Null Pointer Trap Zone）**”，专门用于捕获空指针和部分野指针的解引用，使我们能在调试的第一时间发现问题。
> 
> 在 Linux , Windows 等主流平台上，空指针的值一般是 0x00000000，空指针陷阱区的大小一般为 64KB 或 4KB。

[[11. 生命周期、内存五区模型、动态内存#2. 内存五区模型|五区模型]] 到段模型的映射：

| 五区模型   | 段模型                   | 说明                                       |
| ------ | --------------------- | ---------------------------------------- |
| 代码区    | **代码段（.text）**        | 存放函数机器码，**只读 + 可执行**                     |
| 常量区    | **只读数据段（.rodata）**    | 存放虚表、字符串字面量、RTTI 等只读数据                   |
| 全局/静态区 | **数据段（.data / .bss）** | 存放已初始化（.data）和未初始化（.bss）的静态/全局变量         |
| 堆区     | **堆（Heap）**           | 动态分配的内存（`new` / `malloc`），位于数据段之后，向高地址增长 |
| 栈区     | **栈（Stack）**          | 局部变量、函数调用帧，位于高地址，向低地址增长                  |
