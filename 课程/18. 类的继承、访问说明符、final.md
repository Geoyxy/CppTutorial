# 类的继承、访问说明符、final

---

## 1. 继承的基本概念

假设你要写一个游戏的两种职业类：

```cpp
// 近卫干员类
class Guard {
private:
	int level = 1;        // 等级
	double hp_ = 1300;    // 血量
	double attack_ = 300; // 攻击力
public:
	void Attack() {...};  // 近卫的攻击逻辑
	void TakeDamage(double damage) {...};
};

// 狙击干员类
class Sniper {
private:
	int level = 1;        // 等级
	double hp_ = 700;     // 血量
	double attack_ = 400; // 攻击力
public:
	void Attack() {...};  // 狙击的攻击逻辑
	void TakeDamage(double damage) {...};
};
```

你会发现，`level_`、`hp_`、`attack_` 和 `TakeDamage()` 在三个类中**完全重复**。如果将来要增加一个“防御力”属性，你就得去两个类里分别修改，如果职业类变得更多，会非常容易出错。

把这两个职业**共有的部分**抽出来，放到一个**基类** 中，然后让 `Guard`、`Sniper` **继承**这个基类。这样，共有的数据和行为只需在基类中写一次。

**继承（inheritance）** 允许我们创建一个 **基类（base class）**（也叫父类 parent class），然后让**派生类（derived class）**（也叫子类 son class）通过继承基类来**复用（reuse）**基类的成员，并在此基础上添加自己特有的属性和行为。

> [!NOTE] **概念**：复用 Reuse
> **复用（reuse）** 是软件工程中的核心思想之一。它指的是 **在开发新功能时，尽可能利用已有的、经过测试的代码，而不是从零开始编写**（即重复造轮子）。
> 
> **复用的目标**：
> 
> |目标|说明|
> |---|---|
> |**提高效率**|减少重复编码，缩短开发周期|
> |**降低错误率**|已有代码通常经过测试，比新写代码更可靠|
> |**统一行为**|多个模块共享同一份代码，保证一致性|
> |**简化维护**|修改一处，多处生效，而不是到处修改|
> 
> **C++ 中的复用机制**：
> 
> |复用方式|说明|关系类型|示例|
> |---|---|---|---|
> |**继承（Inheritance）**|派生类复用基类的成员|**"是一种"（is-a）**|`Cat` 继承 `Animal`|
> |**组合（Composition）**|一个对象包含另一个对象|**"有一个"（has-a）**|`Car` 包含 `Engine`|
> |**模板（Template）**|同一套代码适用于多种类型|**"适用于"（适用于任意 T）**|`std::vector<int>`|
> |**函数调用**|直接调用已有的函数|**"使用"（use）**|`std::sort(vec.begin(), vec.end())`|

## 2. 继承的语法

继承类时需要在派生类的类名后加**派生列表（derivation list）**，语法：

```cpp
class 派生类 : 访问说明符 基类
{
	...
};
```

其中的“访问说明符”也叫作“基类访问说明符”、“继承方式”。

例如：

```cpp
// 干员类（基类，里面存通用的成员）
// 这里把数据成员放 public: 下仅供演示，别学
class Operator {
public:
	int level = 1;        // 等级
	double hp_ = 1300;    // 血量
	double attack_ = 300; // 攻击力
	void TakeDamage(double damage) {...};
}

// 近卫干员类（干员类的派生类）
class Guard : public Operator {
public:
	void Attack() {...}; // 近卫的攻击逻辑
}

// 狙击干员类（干员类的派生类）
class Sniper : public Operator {
public:
	void Attack() {...}; // 狙击的攻击逻辑
};
```

通过继承，派生类对象会拥有基类对象（即拥有**基类子对象 base‑class subobject**）。这意味着，当你创建一个派生类对象时，派生类对象的**内存布局**大致如下（简化版）：

```text
|-----------------------|  <-- 派生类对象起始地址
|  基类 A 的数据成员      |  <-- 完整的基类子对象（包含 A 的所有成员，无论访问权限）
|  (int pub, prot, priv)|
|-----------------------|
|  派生类 B 的数据成员    |  <-- 派生类自己新增的成员
|  (int b_data)         |
|-----------------------|
```

但是以上描述只是物理 / 内存上的，实际访问基类子对象的成员**只需要**在成员名前加 `派生类对象.` 前缀，而非 `派生类对象.基类子对象.` 前缀。例如：

```cpp
Guard guard();
guard.Attack();                // 访问 guard 自己的成员
std::cout << guard.hp_; // 直接访问基类子对象的成员
```

虽然派生类**理论上**能访问基类成员，但是实际还需要由访问权限决定是否能访问。

## 3. 访问说明符

前面我们只学过部分访问说明符 `public`, `private` 的部分特点，现在我们会完整地学习访问说明符。

### 3.1 不涉及继承时

对于一个类 `A`，`A` 有成员 `a`：

- **首列**：类 `A` 中某个成员 `a` 的访问权限。
- 首**行**：在哪个位置访问 `a`。
- 单元格：该位置能否访问 `a`。

|  `a` 的访问权限  | 在 `A` 内访问 | 在 `A` 外访问 |
| :---------: | :-------: | :-------: |
|  `public`   |     ✅     |     ✅     |
|  `private`  |     ✅     |     ❌     |
| `protected` |     ✅     |     ❌     |

从以上表格可以看出在不涉及继承时，`protected` 的效果和 `private` 等同。若看不懂以上表格，请回顾 [[13. 类和对象基础、访问说明符#2. 访问说明符|13-2. 访问说明符]] 。

### 3.2 涉及继承时

当涉及继承时，访问说明符可以出现在类的两个位置——**成员访问标签**和**派生列表**，两个位置的访问说明符**都能影响**一个成员最终可在哪里被访问。

对于派生类 `B` 继承基类 `A`，`A` 有一个成员 `a`：

```cpp
class A {
访问说明符:
	int a;
}

class B : 访问说明符 A {...};
```

> [!TIP] **提示**：以下的“`a` 在 `B` 中的访问权限”的作用
> （请先看完 3.2.1 - 3.2.3 再返回看此条）
> 我们知道，当 `B` 继承自 `A`  时，需要先知道 `a` 在 `A` 中的访问权限才能判断：能否通过 `B` 的对象访问 `a`；同理，派生类  ` C ` 继承 ` B ` 时，需要先知道 `a` 在 `B` 中的访问权限才能判断：能否通过 `C` 的对象访问 `a`。

#### 3.2.1 public 继承方式

对于：

```cpp
class B : public A {...};
```

| `a`  在 `A` 中的访问权限 | `a` 在 `B` 中的访问权限 |
| :---------------: | :--------------: |
|     `public`      |     `public`     |
|    `protected`    |   `protected`    |
|     `private`     |    `private`     |

以下表格中：

- **首列**：类 `A` 中某个成员 `a` 的访问权限。
- 首**行**：在哪个位置访问 `a`。
- 单元格：该位置能否访问 `a`。

| `a` 的访问权限           | 在 `A` 内访问 | 在 `B` 内访问 | 通过 `A` 对象访问 | 通过 `B` 对象访问 |
| ------------------- | :-------: | :-------: | :---------: | :---------: |
| ** `public` 成员**    |     ✅     |     ✅     |      ✅      |      ✅      |
| ** `protected` 成员** |     ✅     |     ✅     |      ❌      |      ❌      |
| ** `private` 成员**   |     ✅     |     ❌     |      ❌      |      ❌      |

```cpp
class A {
public:
	int a;
};

class B : public A {
public:
	void Test() { std::cout << a }; // ✅ B 内访问 a
};

B b_instance;
b_instance.a; // ✅ 通过 B 对象访问 a
```

#### 3.2.2 protected 继承方式

对于：

```cpp
class B : protected A {...};
```

| `a`  在 `A` 中的访问权限 | `a` 在 `B` 中的访问权限 |
| :---------------: | :--------------: |
|     `public`      |   `protected`    |
|    `protected`    |   `protected`    |
|     `private`     |    `private`     |

以下表格中：

- **首列**：类 `A` 中某个成员 `a` 的访问权限。
- 首**行**：在哪个位置访问 `a`。
- 单元格：该位置能否访问 `a`。

| `a` 的访问权限           | 在 `A` 内访问 | 在 `B` 内访问 | 通过 `A` 对象访问 | 通过 `B` 对象访问 |
| ------------------- | :-------: | :-------: | :---------: | :---------: |
| ** `public` 成员**    |     ✅     |     ✅     |      ✅      |      ❌      |
| ** `protected` 成员** |     ✅     |     ✅     |      ❌      |      ❌      |
| ** `private` 成员**   |     ✅     |     ❌     |      ❌      |      ❌      |

```cpp
class A {
public:
	int a;
};

class B : protected A {
public:
	void Test() { std::cout << a }; // ✅ B 内访问 a
};

B b_instance;
b_instance.a; // ❌ 错误：不能通过 B 对象访问 a
A().a;        // ✅ 通过 A 对象访问 a
```

> [!TIP] **提示**：`protected` 的使用频率
> 实际开发中几乎用不到 `protected` 基类访问说明符，它的频率在三种继承方式中最低。
#### 3.2.3 private 继承方式

对于：

```cpp
class B : private A {...};
```

| `a`  在 `A` 中的访问权限 | `a` 在 `B` 中的访问权限 |
| :---------------: | :--------------: |
|     `public`      |    `private`     |
|    `protected`    |    `private`     |
|     `private`     |    `private`     |

以下表格中：

- **首列**：类 `A` 中某个成员 `a` 的访问权限。
- 首**行**：在哪个位置访问 `a`。
- 单元格：该位置能否访问 `a`。

| `a` 的访问权限           | 在 `A` 内访问 | 在 `B` 内访问 | 通过 `A` 对象访问 | 通过 `B` 对象访问 |
| ------------------- | :-------: | :-------: | :---------: | :---------: |
| ** `public` 成员**    |     ✅     |     ✅     |      ✅      |      ❌      |
| ** `protected` 成员** |     ✅     |     ✅     |      ❌      |      ❌      |
| ** `private` 成员**   |     ✅     |     ❌     |      ❌      |      ❌      |

```cpp
class A {
protected:
	int a;
};

class B : private A {
public:
	void Test() { std::cout << a }; // ✅ B 内访问 a
};

B b_instance;
b_instance.a; // ❌ 错误：不能通过 B 对象访问 a
A().a;        // ✅ 通过 A 对象访问 a
```

> [!TIP] **提示**：`private` 的使用频率
> 实际开发中很少用 `private` 基类访问说明符，业务开发中更推荐用“**组合**”。

> [!NOTE] **概念**：组合 Composition
> 对比继承的 “`is-a`”（是一个）关系，**组合**是一种“`has-a`”（有一个）关系。组合让一个类通过**成员变量**的方式持有另一个类的对象，从而复用其功能。
> 
> 与 `private` 继承相比，组合有以下优势：
> 
> 1. **更清晰**：一眼就能看出类之间的关系是“拥有”而非“是一种”。
> 2. **更安全**：不会无意中暴露基类的接口。
> 3. **更灵活**：可以在运行时替换被持有的对象。
> 
> ```cpp
> class Engine { /* ... */ };
> 
> class Car {
> private:
> 	// Car 拥有一个 Engine（组合），而不是继承 Engine
>     Engine engine_;
> };
> ```

> [!QUESTION] **问题**：继承时派生类对象不是已经拥有（组合）基类子对象了吗？
> **从内存布局上看，这个说法完全正确**——派生类对象确实“拥有”一个基类子对象，这在物理上就是组合。但在逻辑（语义）上，我们不把物理上的这种组合视作组合。
> 
> 因为**底层实现**和**高层抽象**是两个层面的东西：
> 
> - **底层（物理/内存）**：派生类对象里确实嵌着一个基类子对象，编译器就是这么干的。从这个角度看，它确实“拥有”基类对象。
>     
> - **高层（语义/接口）**：**继承表达的是 `is-a`（是一种）**，比如派生类 `Cat` 是一种 `Animal`。**组合表达的是 ` has-a `（有一个）**，比如 `Car` 有一个 `Engine`。

## 4. 继承中的构造和析构

### 4.1 构造

当我们创建一个派生类的对象时，构造顺序为先构造基类子对象，再构造派生类对象，例如：

```cpp
class A {
public:
    A() { std::cout << "A 构造\n"; }
};

class B : public A {
public:
    B() { std::cout << "B 构造\n"; }
};

int main() {
    B b;   // 输出：A 构造（换行）B 构造
    return 0;
}
```

以上示例代码中，`B` 的构造函数中没有显示调用 `A` 的构造函数，这时编译器会在 `B` 的构造函数中**隐式调用** `A` 的默认构造函数。这也意味着：**当基类没有默认构造函数时必须显式在派生类的构造函数中调用基类的构造函数，且应该把基类的构造函数调用写在派生类构造函数的初始化列表**。例如：

```cpp
class A {
private:
	const int id_;
public:
	// 自定义了构造函数，编译器不再生成隐式默认构造函数
	A(int id) : id_(id) {
		std::cout << "A 构造\n";
	}
};

class B : public A {
private:
	const int id_;
public:
	// 显示调用基类的构造函数，并在初始化列表调用
	B(int a_id, int b_id) : A(a_id), id_(b_id) {
	    std::cout << "B 构造\n";
	}
};

int main() {
    B b;   // 输出：A 构造（换行）B 构造
    return 0;
}
```

### 4.2 析构

析构顺序正好与构造顺序**相反**：先析构派生类对象，再析构基类对象，例如：

```cpp
class A {
public:
    ~A() { std::cout << "A 析构\n"; }
};

class B : public A {
public:
    ~B() { std::cout << "B 析构\n"; }
};

int main() {
    B b;
    return 0;   // 输出：B 析构（换行）A 析构
}
```

和构造时不同，不需要我们再显式调用析构函数。

## 5. final 说明符

`final` 属于**虚说明符 (virt‑specifier)**，它有两种用途：

1. 修饰类时阻止该类被继承。  
2. 修饰虚函数时阻止派生类重写。

这一讲我们只学习第一种用途，第二种用途将在 [[19. 类的多态、virtual、override、final、菱形继承#3. final 说明符|19-3. final 说明符]] 学到。

在类名后面加上 `final`，表示这个类**不能再被作为基类**，例如：

```cpp
// 被 final 说明的类
class Base final {
    ...
};

// ❌ 错误：Derived 试图继承 final 类 Base
class Derived : public Base {
    ...
};
```

`final` 的这种用法主要用于**设计意图的表达**和**编译期约束**：

| 作用         | 说明                                                      |
| ---------- | ------------------------------------------------------- |
| **明确设计意图** | 告诉代码的维护者：“这个类不是设计用来被继承的”                                |
| **防止意外继承** | 有人不小心继承了它，编译器会报错，而不是默默运行                                |
| **编译器优化**  | 编译器知道该类没有派生类后，可以对虚函数调用进行去**虚拟化（devirtualization）**，提升性能 |

## 6. 多层继承和多重继承

| 概念       | 定义                         | 关系           | 例子                                                   |
| -------- | -------------------------- | ------------ | ---------------------------------------------------- |
| **多层继承** | 一个类有一个**基类，一个基类又有一个自己的基类** | 形成继承链        | `class C : public B {};`<br>`class B : public A {};` |
| **多重继承** | 一个类有 **多个直接基类**            | 一个派生类 ← 多个基类 | `class C : public A, public B {};`                   |

### 6.1 多层继承 Multilevel Inheritance

多层继承是最常见、也最容易理解的继承形式——**继承层次（inheritance hierarchy）**（也叫继承链 inheritance chain）逐层向下传递。

```text
┌─────────────┐
│     A       │  ← 最上层的基类
└──────┬──────┘
       │
┌──────┴──────┐
│     B       │  ← 中间层派生类（继承 A）
└──────┬──────┘
       │
┌──────┴──────┐
│     C       │  ← 最底层派生类（继承 B）
└─────────────┘
```

继承层次上每一层派生类都会**累积**其上所有基类的成员：

```cpp
class A {
public:
    int a_val_;
};

class B : public A {
public:
    int b_val_;
};

class C : public B {
public:
    int c_val_;
};

int main() {
    C c;
    c.a_val_ = 1;   // 来自 A
    c.b_val_ = 2;   // 来自 B
    c.c_val_ = 3;   // 自己的
    return 0;
}
```

构造顺序：A → B → C
析构顺序：C → B → A

> [!TIP] **提示**：基类和派生类的相对性
> 基类是相对而言的，对于前面的继承层次示例，并非只有 `A` 才是基类，而是 `A` 是 `B` 和 `C` 的基类，`B` 是 `C` 的基类；同理，派生类也是相对而言的。

### 6.2 多重继承 Multiple Inheritance

多重继承允许一个派生类**同时继承多个基类**。

```text
┌─────────────┐     ┌─────────────┐
│      A      │     │      B      │
└──────┬──────┘     └──────┬──────┘
       └────────┬──────────┘
                │
         ┌──────┴──────┐
         │      C      │  ← 同时继承 A 和 B
         └─────────────┘
```

```cpp
class A {
public:
    int a_val_;
};

class B {
public:
    int b_val_;
};

class C : public A, public B { // 多重继承
public:
    int c_val_;
};

int main() {
    C c;
    c.a_val_ = 1;   // 来自 A
    c.b_val_ = 2;   // 来自 B
    c.c_val_ = 3;   // 自己的
    return 0;
}
```

多重继承的构造顺序：**按照派生列表中基类出现的顺序**（A → B → C）

> [!WARNING] **注意**：避免使用多重继承
> 多重继承**普遍会导致二义性问题**：当多个基类中有同名成员时，派生类无法确定访问的是哪一个。
>
>```cpp
> class A { public: int value_ = 10; };
> class B { public: int value_ = 20; };
>
>class C : public A, public B {};
>
>int main() {
>    C c;
>    // std::cout << c.value_; // ❌ 二义性错误
>    std::cout << c.A::value_; // ✅ 使用限定名 10
>    std::cout << c.B::value_; // ✅ 使用限定名 20
>    return 0;
>}
>```
>
> 以上所举的问题只是多重继承带来的问题的冰山一角，下一讲的 [[19. 类的多态、virtual、override、final、菱形继承#6. 菱形继承 Diamond Inheritance| 19-6. 菱形继承]] 也是多重继承导致的棘手问题之一，因此==**实际开发中谨慎使用多重继承**==，推荐一个派生类继承**一个普通类或抽象类**，以及**若干个纯抽象类**（即接口）。

关于抽象类和纯抽象类，我们将在下一讲中学到。

## 7. 继承中的名字隐藏

当派生类中定义了与基类**同名**的成员（变量或函数）（也就是说对函数而言是直接看标识符相同而非函数签名相同）时，基类中的同名成员会被**隐藏**，派生类中直接使用该名字时，访问的是派生类自己的成员。

若要访问被隐藏的成员，应该使用**限定名**（即指定作用域）。

```cpp
class A {
public:
    void Func() { std::cout << "A::Func()\n"; }
    void Func(int) { std::cout << "A::Func(int)\n"; }  // 重载
};

class B : public A {
public:
    void Func() { std::cout << "B::Func()\n"; }   // 同名，隐藏 A::Func
};

int main() {
    B b;
    b.Func();      // ✅ 调用 B::Func()
    // b.Func(10); // ❌ 错误！A::Func(int) 被隐藏了
	b.A::Func();   // ✅ 通过作用域解析运算符显式调用
    b.A::Func(10);
    return 0;
}
```

输出：

```text
B::Func()
A::Func()
A::Func(int)
```
