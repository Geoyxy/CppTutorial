## 1. 函数指针 Function Pointer

函数指针是 C++ 中一种**指向函数而不是指向数据**的指针。它指向的函数具体是**全局函数**和**静态成员函数**，而不是非静态成员函数。它存储的是**函数的入口地址**（即函数机器码在代码区中的起始位置），通过它可以间接调用该函数。

1. 声明语法：

```cpp
返回值类型 (*指针名)(参数类型列表)
```

例如：

```cpp
void (*p)(int, double);
```

声明一个函数指针 `p`，指向一个接受 `int` 和 `double`、返回 `void` 的函数。

2. 赋值

```cpp
// 用函数名赋值（函数名会被隐式转换为函数指针）
void Func(int x, double y) { ... }

// 两种初始化写法
void (*p2)(int, double) = &Func;
void (*p1)(int, double) = Func; // 或 Func 隐式转换为 &Func

// 两种赋值写法
p1 = &Func;
p2 = Func; // 或 Func 隐式转换为 &Func
```

3. 调用

```cpp
// 两种调用写法
p(10, 3.14);
(*p)(10, 3.14);
```

完整示例：

```cpp
#include <iostream>

// 普通函数
int Add(int a, int b) {
    return a + b;
}

int Multiply(int a, int b) {
    return a * b;
}

int main() {
    // 声明一个函数指针，指向接受两个 int、返回 int 的函数
    int (*func_ptr)(int, int);

    // 指向 Add
    func_ptr = Add;
    std::cout << func_ptr(3, 4) << std::endl;   // 输出：7

    // 指向 Multiply
    func_ptr = Multiply;
    std::cout << func_ptr(3, 4) << std::endl;   // 输出：12

    return 0;
}
```

## 2. 成员函数指针 Pointer to Member Function

成员函数指针是 C++ 中一种**特殊的指针**，它指向**类的非静态成员函数**。它与普通函数指针有本质区别，因为成员函数必须通过**对象**才能调用（因为它隐含了 `this` 指针）。

| 对比维度          | 普通函数指针      | 成员函数指针                |
| ------------- | ----------- | --------------------- |
| **指向**        | 全局函数 / 静态函数 | 类的**非静态成员函数**         |
| **包含信息**      | 只有函数入口地址    | 函数入口地址 + 需要 `this` 指针 |
| **调用方式**      | 直接调用（不需要对象） | **必须通过对象**或对象指针调用     |
| **大小（64位）**   | 8 字节        | **16 字节**（或更大，取决于编译器） |
| **能否转换为普通指针** | ✅ 可以        | ❌ **不能**（类型完全不同）      |

1. 声明语法：

```cpp
返回值类型 (类名::*指针名)(参数类型列表);
```

例如：

```cpp
class Dog {
public:
    void Bark() { std::cout << "Woof!\n"; }
    void Eat(int amount) { /* ... */ }
};

// 声明一个成员函数指针，指向 Dog 的成员函数，无参数，无返回值
void (Dog::*ptr)();
```

2. 赋值：

```cpp
void (Dog::*ptr)() = &Dog::Bark;   // 必须使用 & 取地址
// 或者
auto ptr = &Dog::Bark;             // C++11 起可用 auto，auto 能自动推断类型
```

> **注意**：`Dog::Bark` 是一个成员函数名，必须用 `&` 取地址（不像普通函数名可以隐式转换）。

3. 调用：

成员函数指针**不能直接调用**，必须通过对象或对象指针：

```cpp
Dog d;
Dog* p = &d;

// 通过对象调用
(d.*ptr)();   // 调用 d.Bark()

// 通过指针调用
(p->*ptr)();  // 调用 p->Bark()
```

> [!TIP] **提示**：成员指针访问运算符
> - `.*`：**成员指针访问运算符**，左操作数是对象，右操作数是成员指针。
> - `->*`：**成员指针访问运算符**，左操作数是对象指针，右操作数是成员指针。
> 
> 关于运算符的更多信息，请参考 [[运算符概览]] 。

完整示例：

```cpp
#include <iostream>

class Calculator {
public:
    int Add(int a, int b) const { return a + b; }
    int Subtract(int a, int b) const { return a - b; }
    int Multiply(int a, int b) const { return a * b; }
};

int main() {
    // 声明成员函数指针
    int (Calculator::*op)(int, int) const;

    Calculator calc;

    // 指向 Add
    op = &Calculator::Add;
    std::cout << (calc.*op)(10, 5) << std::endl;   // 15

    // 指向 Subtract
    op = &Calculator::Subtract;
    std::cout << (calc.*op)(10, 5) << std::endl;   // 5

    // 指向 Multiply
    op = &Calculator::Multiply;
    std::cout << (calc.*op)(10, 5) << std::endl;   // 50

    return 0;
}
```

> [!TIP] **提示**：简化类型写法
> 要简化类型写法，请参考：
> 1. [[CPab1. auto#3.4 auto 与成员函数指针]]：自动推动类型。
> 2. [[CPaa1. 类型别名 Type Alias#2.2 复杂类型别名]]：简化类型名。

## 3. 对象的内存模型

### 3.1 对象的内存模型的基本概念

在 C++中，对象在内存中如何布局，直接决定了 `sizeof` 的结果、指针运算、以及多态的实现。理解对象的内存模型，是理解 C++**底层行为**的关键。

类和对象中各成员在内存中的分布：

| 成员类型                    | 存储位置（五区模型）       | 说明                                   |
| ----------------------- | ---------------- | ------------------------------------ |
| **非静态数据成员**（普通成员变量）     | **栈区** 或 **堆区**  | 随对象所在位置而定。对象在栈上，成员就在栈上；对象在堆上，成员就在堆上。 |
| **虚表指针（vptr）**          | **栈区** 或 **堆区**  | 作为对象的隐藏成员，随对象存储。                     |
| **静态数据成员（`static`）**    | **全局/静态区**       | 类所有对象共享一份，程序启动时分配，结束时释放。             |
| **类型信息（RTTI）**          | **常量区**          | 通常与虚表关联，存储类名、类型信息等。                  |
| **虚表（vtable）**          | **常量区**          | 类级别的静态数据，存储虚函数地址数组。                  |
| **字符串字面量**（如 `"Hello"`） | **常量区**          | 只读，不可修改。                             |
| **`const` 全局常量**        | **常量区**（可能）      | 取决于编译器优化，通常在常量区。                     |
| **`constexpr` 常量**      | **常量区**（或直接嵌入代码） | 编译期常量，可能直接放入代码区或常量区。                 |
| **成员函数（非静态）**           | **代码区**          | 函数的机器码，所有对象共享。                       |
| **静态成员函数（`static`）**    | **代码区**          | 与普通成员函数一样，也在代码区。                     |
| **虚函数（`virtual`）**      | **代码区**          | 函数本体在代码区。                            |

### 3.2 只有非静态数据成员的对象

对于一个没有虚函数的类，其对象的内存布局非常简单：**按照声明顺序，依次存储其非静态数据成员**。成员函数不存储在对象的内存中，而是存储在代码区中。

```cpp
class Point {
public:
    int x_;  // 4 字节
    double y_;  // 8 字节
    void Print() const; // 不占对象空间
};

int main() {
    std::cout << sizeof(Point) << " 字节"; // 输出 16 字节
    return 0;
}
```

![[只有非静态数据成员对象的内存布局.png]]

观察上图，你会发现 `x_` 和 `y_` 之间的内存为“填充字节”，这是**内存对齐**规则导致的。

### 3.3 内存对齐 Memory Alignment

#### 3.3.1 内存对齐的基本概念

**内存对齐**是编译器在布局结构体/类的成员时，为了**提高 CPU 访问效率**而采取的一种策略：**每个成员变量在内存中的起始地址，必须是其自身大小（或对齐要求）的整数倍。**

内存对齐的原因：

| 原因            | 说明                                                                               |
| ------------- | -------------------------------------------------------------------------------- |
| **硬件要求**      | 某些 CPU 架构（如 ARM、RISC）强制要求对齐，访问未对齐的地址会直接崩溃（触发硬件异常）。                               |
| **性能优化**      | 现代 CPU 以“字”（word，通常 4/8 字节）为单位读取内存。如果变量地址对齐，一次就能读完；如果未对齐，CPU 需要额外读取多次并拼接，严重影响性能。 |
| **原子操作与并发安全** | 在 x86/x64 上，对齐的内存访问是原子的（对于基础类型），未对齐则不是，会导致并发问题。                                  |
| **跨平台兼容性**    | 不同硬件平台的对齐要求不同，编译器默认对齐方式能提升代码的可移植性。                                               |

#### 3.3.2 对齐要求

**对齐要求（alignment requirement）**（也叫作**对齐值 alignment value**）：**一个对象的起始地址必须是某个数值 N 的整数倍**，其中 N 即该类型的对其要求 / 对齐值。

windows 平台、64 位系统中常见类型的对齐要求：

| 类型                 | 大小（字节） | 对齐要求（字节） |
| ------------------ | ------ | -------- |
| `char`             | 1      | 1        |
| `bool`             | 1      | 1        |
| `short`            | 2      | 2        |
| `int`              | 4      | 4        |
| `float`            | 4      | 4        |
| `double`           | 8      | 8        |
| `long long`        | 8      | 8        |
| `void*`（指针）        | 8      | 8        |
| `struct` / `class` | 视成员而定  | 见下       |

**规律**：

- 对齐要求必须是 2 的幂（1, 2, 4, 8, 16 ...）
- 基础类型的对齐要求 = 其自身大小。
- 指针的对齐要求 = 8（64 位系统）或 4（32 位系统）。
- 结构体 / 类的对齐要求 = ** `max(所有非静态数据成员的对齐要求, 所有直接基类的对齐要求)` ** 。

另外，对象的总大小（字节）也必须是其自身对齐要求的倍数，否则要在对象的末尾追加填充字节来完成此要求（见 [[#3.8 多重继承 + 虚函数的对象]] 的示例）。

> **提示**：“max(a, b)” 指的是 a 和 b 中的最大值。

例如：

```cpp
class Point {
public:
    int x_;  // 4 字节
    double y_;  // 8 字节
    void Print() const; // 不占对象空间
};

int main() {
	Point point;
	sizeof(Point);  // 输出：16
	alignof(Point); // 输出：8，alignof(T) 输出 T 的对齐要求
	return 0;
}
```

![[只有非静态数据成员对象的内存布局.png]]

1. `point` 的对齐要求是 `max(sizeof(x_), sizeof(y_)) = 8`，而 0x0000 = 0 = 8 * 0，即 `point` 的起始地址为 8 的倍数，符合要求
2. `x_` 的对齐要求是 4，`x_` 的（以对象起始地址为基地址的）偏移量 0 为 4 的倍数，符合要求。
3. `y_` 的对齐要求是 8，`y_` 的（以对象起始地址为基地址的）偏移量 8 为 8 的倍数，符合要求。
4. 因为数据成员在对象内存中的顺序是按声明顺序排列的，所以 `x_` 后的成员必须为 `y_`，又因为符合要求的 `y_` 的最小（以对象起始地址为基地址的）偏移量为 8，所以中间的 `0x0004` - `0x0007` 无法存储任何对象，为填充字节。
5. `point` 占用的偏移为 15，总大小为 16 字节，且 16 为 `point` 的对齐要求 8 的倍数，所以末尾不需要 再追加填充字节。

#### 3.3.3 alignof 运算符

`alignof` 是 C++11 引入的一个**运算符**，用于**查询一个类型或变量在内存中的“对齐要求”**。

```cpp
alignof(类型)
```

返回一个 `std::size_t` 类型的值，表示 `类型` 的对齐字节数。

```cpp
std::cout << "char:   " << alignof(char) << std::endl;    // 1
std::cout << "short:  " << alignof(short) << std::endl;   // 2
std::cout << "int:    " << alignof(int) << std::endl;     // 4
std::cout << "double: " << alignof(double) << std::endl;  // 8
std::cout << "int*:   " << alignof(int*) << std::endl;    // 8（64位系统）
```

#### 3.3.4 alignas

`alignas` 是 C++11 引入的**对齐说明符（alignment specifier）**，用于**显式指定**一个类型或变量的对齐要求。它让我们能覆盖编译器默认的对齐方式，强制对象按特定的字节边界对齐。

```cpp
alignas(对齐值) 类型 变量名;
alignas(对齐值) struct/class 类型名 { ... };
```

```cpp
alignas(16) int x;      // x 的地址必须是 16 的倍数
alignas(64) double d;   // d 的地址必须是 64 的倍数

struct alignas(32) MyStruct {
    char c;
    int i;
    double d;
};

int main() {
    std::cout << alignof(MyStruct) << std::endl;  // 32
    std::cout << sizeof(MyStruct) << std::endl;   // 至少是 32（对齐值的倍数）
    return 0;
}
```

### 3.4 有虚函数的对象

当一个类中声明了虚函数，那么这个类的对象会自动生成一个叫**虚表指针（vptr）**的数据成员，且 vptr 的起始地址和对象的起始地址一定重叠（对于 GCC, MSVC 等主流编译器采用的 C++ 二进制布局规范而言）。

> **提示**：关于“vptr”我们会在稍后学到，这里仅需知道存在 vptr 这个数据成员。

其余非静态数据成员的内存规则布局规则不变。

```cpp
// 64 位系统
class Point {
public:
    char sym_ = '*';
    virtual void Print() const; // 不占对象空间
    virtual ~Point() = default;
}
```

### 3.5 单一继承的对象

派生类对象包含**基类子对象**，派生类自己的成员排在基类子对象之后。

```cpp
class Base {

class Derived : public Base {

```

// 64 位系统
class Base {

class Base1 { int b1_; }; // 4 字节

### 3.8 多重继承 + 虚函数的对象

多重继承中，当一个基类有虚函数时，这个基类会有自己的 vptr，也就是说多继承中可能会出现多个 vptr，而派生类不会有自己的 vptr。

```cpp
class Base1 { // 以下表格中简称 B1
public:
    virtual void F1() {}
    int b1_;
};

class Base2 { // 以下表格中简称 B2
public:
    virtual void F2() {}
    int b2_;
};

class Derived : public Base1, public Base2 {
public:
    void F1() override {}
    void F2() override {}
    int d_;
};
```

### 3.10 空类的对象

一个没有任何非静态数据成员的类称为**空类**。
C++ 标准规定：空类对象**不能拥有 0 字节大小**；对象必须拥有唯一地址标识，所以编译器会自动插入 1 字节的**空类占位字节**。

```cpp
class A {
public:	
};
// 或
class A {
public:
	static int val;
	static inline int num = 0;
};
```

![[空类对象的内存布局.png]]

**空基类优化 (Empty Base Optimization，EBO)**：当空类作为基类被继承时，派生类对象里的这个空基类子对象，不需要占用额外空间，空类占位字节可以被优化掉。

```cpp
class A {};
class B : public A {};
```

![[空基类优化内存布局.png]]

图中对象 `b` 中本应该还有 `A` 的子对象的空类占位字节，但因为 EBO，所以实际上 `b` 中只有自己的空类占位字节。

## 4. 动态多态底层原理

动态多态（运行时多态）在 C++ 中的实现依赖于 **虚表（vtable）**（也叫**虚函数表**） 和 **虚表指针（vptr）** 这两个核心机制。这一章节让我们来剖析其底层工作方式。

### 4.1 虚表 vtable

当一个类中存在虚函数时，编译器会在**编译期**生成一个**虚表**并存储在**只读数据段（.rodata）**。虚表**本质上**就是一个存储函数地址的**数组**，类中的**所有虚函数**会按它们的**声明顺序**存储在类的虚表中。

例如：

```cpp
// 64 位系统
class Animal {
	virtual void Eat() { ... };
	virtual void Speak() { ... };
	virtual ~Animal() = default;
};
```

![[虚表.png|400]]

**槽位（Slot）** 是虚表中的一个**逻辑位置**，每个槽位存储一个虚函数的地址。它是一个**抽象概念**，用于描述虚表中“第几个位置”，与偏移量（Offset）对应但不完全等同。

仅当通过动态多态（即通过“基类指针/引用”指向派生类对象）调用虚函数时，才会通过虚表调用函数。也就是说，虚表相当于一个调用虚函数时的枢纽（中转站），之所以这么设计是为了实现动态多态。

```cpp
class Animal {
	virtual void Eat() { ... };
	virtual void Speak() { ... };
	virtual ~Animal() = default;
};

class Dog : public Animal {
	void Eat() override { ... };
	void Speak() override{ ... };
}

int main() {
	Dog dog;
	Dog* dog_ptr = &dog;
	Animal* animal_ptr = &dog;
	dog_ptr->Speak();    // ❌ 非动态多态
	animal_ptr->Speak(); // ✅ 动态多态，基类指针调用指向派生类对象
	return 0;
}
```

### 4.2 多层继承中的虚表

[[18. 类的继承、访问说明符、final#6.1 多层继承 Multilevel Inheritance|多层继承]]（`Derived` 继承 `Base`，`Base` 继承 `Root`）中，虚表的构建规则是：**派生类会在基类虚表的基础上“追加”新虚函数，已有的虚函数槽位保持不变。**

具体来说，在一个 [[18. 类的继承、访问说明符、final#6.1 多层继承 Multilevel Inheritance|继承层次]] 中：

1. **基类先构建**：编译器为最顶层的基类（如 `Root`）生成虚表，将其虚函数按声明顺序填入槽位 0、1、2……。
2. **派生类复制并替换**：当编译器处理派生类（如 `Base`）时，它会**复制**基类的虚表，然后**用派生类中重写的函数地址覆盖**对应的槽位（如用 `Base::ToString` 覆盖槽位 1）。
3. **派生类追加新函数**：接着，编译器将派生类中**新增的虚函数**（如 `Base::PrintInfo`, ......）按声明顺序**追加**到虚表的末尾（放在槽位 2, 3, ......）。

例如：

```cpp
class Root {
public:
	void EmptyFunc() { ... };
	virtual Id GetId() { ... };
	virtual std::string ToString() { ... };
};
```

![[多层继承中的虚表-Root.png|400]]

```cpp
class Base : public Root{
public:
	std::string ToString() override { ... };
	virtual void PrintInfo() { ... };
};
```

![[多层继承中的虚表-Base.png|400]]

> [!WARNING] **注意**：虚析构函数的重写
> 基类的虚表中有虚析构函数时，派生类类会用自己的虚析构函数**覆盖**虚表中基类的虚析构函数。
> 
> ```cpp
> class A {
> public:
> 	virtual ~A() = default;
> };
> 
> class B : public A {
> public:
> 	virtual ~B() = default;
> }
> ```
> 
> |  类  |      虚表      |
| :-: | :----------: |
| `A` | 槽位 0：`A::~A` |
| `B` | 槽位 0：`B::~B` |


### 4.3 多重继承中的虚表

[[18. 类的继承、访问说明符、final#6.2 多重继承 Multiple Inheritance|多重继承]] 中，派生类会为每个含虚函数的基类生成一张独立的虚表。例如：

1. 一个 [[18. 类的继承、访问说明符、final#6.1 多层继承 Multilevel Inheritance|继承层次]] 中，每个有虚函数的基类都有一个虚表，存储有各自的虚函数：

```cpp
class Base1 {
public:
	virtual void Func1() { ... }
	virtual void Func2() = 0;
};

class Base2 {
public:
	void Func3() {}
	virtual void Func4() = 0;
};
```

![[多重继承中的虚表-Base.png]]

2. 派生类会复制两个基类的虚表，对于派生类重写的函数：
	- 若该函数来源于派生列表中的第一个基类，则用该函数的地址覆盖对应的槽位。
	- 若该函数来源于派生列表中的其他基类，则用该函数的 `thunk`（调整桩）的地址覆盖对应的槽位。
3. 将自己的虚函数**追加**到第一个基类（即派生列表中的第一个基类）的虚表的末尾。

```cpp
class Derived : public Base1, public Base2 {
public:
	void Func2() override { ... }
	void Func4() override { ... }
	virtual void Func5() = 0;
};
```

![[多重继承中的虚表-Derived.png]]

> **提示**：关于 `thunk`（调整桩），我们会在稍后的 vptr 部分了解到。

### 4.4 多层继承中的 vptr

**vptr**（虚表指针）是对象内部的一个**隐藏指针**，指向该类对应的**虚表（vtable）**。它是 C++ 实现运行时多态（即动态多态）的“连接器”——**在运行期**，通过它，程序才能在运行时找到正确的虚表。（**编译期**的编译器不需要 vptr 也能知道虚表的地址）

在本节的 [[#3.5 单一继承 + 虚函数的对象]] 中，我们已经了解到：若基类有虚函数，派生类会**共享基类的 vptr**，而不是新建一个。

在此，我们还需要了解到的是：

派生类对象共享基类的 vptr 时，会使该 vptr **指向自己的虚表**（原本 vptr 是指向的基类的虚表）。

```cpp
class A {
public:
    virtual void Func1() {}
	virtual ~A() = default;
};

class B : public A {
public:
    void Func1() override {}
};

class C : public B {
public:
    void Func1() override {}
};

int main() {
    C c; // c 的 vptr 指向 C 的虚表
    B b; // b 的 vptr 指向 B 的虚表
    A a; // a 的 vptr 指向 A 的虚表
    return 0;
}
```

这样，程序才能在运行时**通过对象的 vptr 找到对应的虚表**以调用指定的函数。

### 4.5 多重继承中的 vptr

在本节的 [[#3.7 多重继承 + 虚函数的对象]] 中，我们已经了解到：多重继承中，当一个基类有虚函数时，这个基类会有自己的 vptr，也就是说多继承中可能会出现多个 vptr，而派生类不会有自己的 vptr。

在此，我们还需要了解到的是：

派生类虽然没有自己的 vptr，但它会**复用**各个基类的 vptr——让这些 vptr **指向自己复制（并修改）过的虚表**——即派生类自己的虚表版本（而非基类原始的虚表）。

```cpp
class A { // 构造虚表 A
public:
    virtual void Func1() {}
    virtual ~A() = default;
};

class B { // 构造虚表 B
public:
    virtual void Func2() {}
	virtual ~B() = default;
};

// 复制并修改 A ，为了区分，我们称复制并修改后的 A 为 A1
// 复制 B ，为了区分，我们称复制后的 B 为 B1
class C : public A, public B {
public:
    void Func1() override {}
};

int main() {
	// c 中第一个 vptr 指向 A1
	// c 中第二个 vptr 指向 B1
    C c;
    B b; // b 的 vptr 指向 B
    A a; // a 的 vptr 指向 A
    return 0;
}
```

> [!TIP] **提示** ：`thunk` 调整桩
> 首先我们需要知道：一个虚函数被谁重写，这个虚函数就会**转而期望谁的 `this` 指针**。
> 
> ```cpp
> class Base1 {
> public:
> 	virtual void Func1() { ... }
> 	virtual void Func2() = 0;
> };
> class Base2 {
> public:
> 	void Func3() {}
> 	virtual void Func4() = 0;
> };
> class Derived : public Base1, public Base2 {
> public:
> 	void Func2() override { ... }
> 	void Func4() override { ... }
> 	virtual void Func5() = 0;
> };
> int main() {
> 	Derived d;
> 	Base1* ptr = &d;
> 	ptr->Func2();
> }
> ```
> 
> 在运行期，`ptr` 指向的是 `d` 的起始地址，同时也是 `Base1` 的 vptr 的起始地址，程序会通过 vptr 找到 `Derived` 复制过的 `Base1` 的虚表，然后找到其中的 `Func2` 函数的地址。
> 
> 因为 `Func2` 被 `Derived` 重写过，所以 `Func2` 期望 `d` 的 `this` 指针，而 `ptr` 指向的是 `d` 的起始地址，等效于 `d` 的 `this`，所以 `ptr` 就被传入 `Func2`。
> 
> ![[多重继承中的虚表-Derived.png]]
> ![[对象d的内存布局.png|300]]
> 
> 假设虚表中存的不是 `Func4` 的 `thunk` 的地址而是 `Func4` 的地址，那么对于以下代码呢？
> 
> ```cpp
> Derived d;
> Base2* ptr = &d;
> ptr->Func4();
> ```
> 
> 在运行期，`ptr` 指向的是 `d` 中 `Base2` 的 vptr 的起始地址（而非 `d` 的起始地址）（因为编译期的编译器会修改 `ptr` 以保证运行期的程序能轻松找到对应的虚表）， 程序会通过 `ptr` 直接找到 vptr ，然后找到 `Derived` 复制过的 `Base2` 的虚表，接着找到其中的 `Func4` 函数的地址。
> 
> 但是光找到 `Func4` 的地址还不行，`Func4` 还期望 `d` 的 `this` 指针，我们可以把 `ptr` 传给 `Func4` 吗？——不行，因为此时 `ptr` 指向的不是 `d` 的起始地址，不能等效于 `d` 的 `this`。
> 
> 所以我们才需要 `thunk` 把 `ptr` 的指向重新偏移到 `d` 的起始地址，然后 `thunk` 再把 `ptr` 传给自己存储的 `Func4` 的地址。
> 
> 其实你能发现 `thunk` 本质上是一个函数，用于调整要传入的指针，其伪代码类似于：
> 
> ```cpp
> // thunk 汇编伪代码（x86-64 风格）
> void thunk_for_Derived_Func4(void* this_ptr) {
>     // 1. 调整 this：从 Base2* 减去偏移量 8，得到 Derived*
>     this_ptr = (char*)this_ptr - 8;
> 
>     // 2. 跳转到真正的 Derived::Func4，并把调整后的 this 传进去
>     goto Derived::Func4(this_ptr);  // 这不是标准 C++，只是表达“跳转”的意思
> }
> ```

### 4.6 多层继承的动态多态实现流程

对于：

```cpp
// 纯抽象类：生命接口
class Life {
public:
	virtual void IsSurvival() = 0; // 是否存活
	virtual ~Life() = default;
};

// 狼类
class Wolf : public Life {
public:
	void IsSurvival() override { ... } // 是否存活
	virtual void Move() { ... }        // 移动
	virtual ~Wolf() = default;
};

// 狗类
class Dog : public Wolf {
public:
	virtual void Guard() { ... } // 看守
	virtual ~Dog() = default;
};

int main() {
    Wolf wolf; // wolf 的 vptr 指向 Wolf 的虚表
    Life* ptr = &wolf;
    ptr->IsSurvival();
    return 0;
}
```

#### 第一步、生成虚表（编译期）

编译器为每个含有虚函数的类生成一张虚表，放在只读数据段（`.rodata`）中：

| 类          | 虚表内容（槽位顺序）                                                                           |
| ---------- | ------------------------------------------------------------------------------------ |
| **`Life`** | 槽位 0: `Life::IsSurvival`  <br>槽位 1: `Life::~Life`                                    |
| **`Wolf`** | 槽位 0: `Wolf::IsSurvival`（重写，覆盖）  <br>槽位 1: `Wolf::Move`（新增）  <br>槽位 2: `Wolf::~Wolf` |

#### 第二步、记录槽位信息（编译期）

编译器看到 `ptr->IsSurvival()` 时：

- 知道 `ptr` 的类型是 `Life*`。
- 查询 `Life` 的虚表布局，发现 `IsSurvival` 在 **槽位 0**。
- 将槽位信息（偏移量 0）写入该调用点的指令中。

#### 第三步、类型检查（编译期）

编译器检查赋值 `Life* ptr = &wolf;` 是否合法：

- 检查 `Wolf` 是否是 `Life` 的公有派生类（是）。
- 检查 `Wolf` 是否实现了 `Life` 的所有纯虚函数（是）。
- 通过检查，生成赋值指令（直接将 `wolf` 的地址赋给 `ptr`，不做任何转换）。

#### 第四步、构造对象 wolf（运行期）

- 在栈上分配 `Wolf` 对象所需的内存（包含 `vptr` + 数据成员）。
- 构造 `Wolf` 对象：
    1. 先构造 `Life` 子对象：`vptr` 指向 `Life` 的虚表。
    2. 再构造 `Wolf` 自己：`vptr` **更新**为指向 `Wolf` 的虚表。
- 现在 `wolf` 的 `vptr` 指向 `Wolf` 的虚表。

#### 第五步、Life* ptr = &wolf（运行期）

- 将 `wolf` 的地址复制到指针 `ptr` 中。
- 此时 `ptr` 指向 `wolf` 对象的起始地址。

#### 第六步、ptr->IsSurvival()（运行期）

1. **通过 `ptr` 读取对象的 `vptr`**：  
    `ptr` 指向 `wolf` 的起始地址，而 `wolf` 起始地址处存储的就是 `vptr`。  
    运行时从该地址读取 8 字节，得到 `Wolf` 虚表的起始地址。
2. **使用编译期确定的槽位偏移量**：  
    编译期已经记录 `IsSurvival` 在 `Life` 虚表的**槽位 0**（偏移量 0），运行时直接用这个偏移量从虚表中取出函数地址。
3. **调用函数**：  
    从虚表取出 `&Wolf::IsSurvival`，跳转到该地址执行（同时将 `wolf` 的地址作为 `this` 指针传入）。

现在你已经理解了**多层继承时的多态**发生了什么，你现在也应该能理解**多重继承时的多态**实现流程，在学习下一章前，请尝试思考一下。

### 4.7 多重继承的动态多态实现流程

对于：

```cpp
class Base1 {
public:
    virtual void Func1() { std::cout << "Base1::Func1\n"; }
    virtual void Func2() { std::cout << "Base1::Func2\n"; }
    virtual ~Base1() = default;
};

class Base2 {
public:
    virtual void Func3() { std::cout << "Base2::Func3\n"; }
    virtual void Func4() { std::cout << "Base2::Func4\n"; }
    virtual ~Base2() = default;
};

class Derived : public Base1, public Base2 {
public:
    void Func1() override { std::cout << "Derived::Func1\n"; }
    void Func3() override { std::cout << "Derived::Func3\n"; }
    virtual void Func5() { std::cout << "Derived::Func5\n"; }
    virtual ~Derived() = default;
};

int main() {
    Derived d;
    Base2* ptr = &d;
    ptr->Func3();
    return 0;
}
```

#### 第一步、生成虚表（编译期）

编译器为每个含有虚函数的类生成独立的虚表，放在只读数据段（`.rodata`）中：

| 类                              | 虚表内容（槽位顺序）                                                                                                                           |
| :----------------------------- | :----------------------------------------------------------------------------------------------------------------------------------- |
| **`Base1`**                    | 槽位 0: `Base1::Func1`<br>槽位 1: `Base1::Func2`<br>槽位 2: `Base1::~Base1`                                                                |
| **`Base2`**                    | 槽位 0: `Base2::Func3`<br>槽位 1: `Base2::Func4`<br>槽位 2: `Base2::~Base2`                                                                |
| **`Derived`（为 `Base1` 准备的虚表）** | 槽位 0: `Derived::Func1`（重写 `Base1::Func1`）<br>槽位 1: `Base1::Func2`（未重写）<br>槽位 2: `Derived::Func5`（新增，追加）<br>槽位 3: `Derived::~Derived` |
| **`Derived`（为 `Base2` 准备的虚表）** | 槽位 0: `Derived::Func3`（重写 `Base2::Func3`）<br>槽位 1: `Base2::Func4`（未重写）<br>槽位 2: `Derived::~Derived`                                  |

#### 第二步、记录槽位信息（编译期）

编译器看到 `ptr->Func3()` 时：

- 知道 `ptr` 的静态类型是 `Base2*`。
- 查询 `Base2` 的虚表布局，发现 `Func3` 在 **槽位 0**。
- 将槽位信息（偏移量 0）写入该调用点的指令中。

#### 第三步、类型检查（编译期）

编译器检查赋值 `Base2* ptr = &d;` 是否合法：

- 检查 `Derived` 是否是 `Base2` 的公有派生类（是）。
- 通过检查，生成赋值指令。

#### 第四步、构造对象 d（运行期）

- 在栈上分配 `Derived` 对象所需的内存。
- 构造过程按继承顺序进行（`Base1` → `Base2` → `Derived`）：
  1. 构造 `Base1` 子对象：`vptr1` 指向 `Base1` 的虚表。
  2. 构造 `Base2` 子对象：`vptr2` 指向 `Base2` 的虚表。
  3. 构造 `Derived` 自己：**`vptr1` 更新为指向 `Derived` 为 `Base1` 准备的虚表**；**`vptr2` 更新为指向 `Derived` 为 `Base2` 准备的虚表**。

#### 第五步、Base2* ptr = &d（运行期）

- 编译器在第三步生成的指令类似于：`ptr = (Base2*)((char*)&d + offset);`

|部分|含义|
|---|---|
|`&d`|获取 `Derived` 对象的起始地址（`Derived*` 类型）|
|`(char*)&d`|将 `Derived*` 转换为 `char*`，以便进行**按字节**的指针算术运算|
|`+ offset`|在地址上增加 `offset` 个字节，使指针移动到 `Base2` 子对象的起始位置|
|`(Base2*)`|将 `char*` 转换回 `Base2*` 类型|

- `ptr` 指向 `d` 对象中的 `Base2` 子对象起始地址（而**不是**整个 `d` 对象的起始地址）。
- 此时 `ptr` 指向的位置存储的是 `vptr2`。

#### 第六步、ptr->Func3()（运行期）

1. **通过 `ptr` 读取对象的 `vptr`**：
   - `ptr` 指向 `Base2` 子对象的起始地址，该地址处存储的是 `vptr2`。
   - 运行时从该地址读取 8 字节，得到 `Derived` 为 `Base2` 准备的虚表的起始地址。

2. **使用编译期确定的槽位偏移量**：
   - 编译期已经记录 `Func3` 在 `Base2` 虚表中的**槽位 0**（偏移量 0）。
   - 运行时直接用这个偏移量从虚表中取出函数地址。

3. **调用函数（含 this 指针调整）**：
   - 从虚表取出的是 `&Derived::Func3` 的地址。
   - **问题**：`ptr` 指向的是 `Base2` 子对象，而 `Derived::Func3` 需要一个指向整个 `d` 对象的 `this` 指针。
   - 编译器在虚表中存储的**不是**直接指向 `Derived::Func3` 的地址，而是指向一个 **`thunk`（调整桩）** 的地址。
   - `thunk` 执行以下操作：
     1. 将 `ptr`（指向 `Base2` 子对象）减去 `Base2` 子对象在 `Derived` 对象中的偏移量，得到整个 `Derived` 对象的起始地址。
     2. 将调整后的地址作为 `this` 指针。
     3. 跳转到真正的 `Derived::Func3` 函数执行。

| 对比维度          | 多层继承                | 多重继承                                    |
| :------------ | :------------------ | :-------------------------------------- |
| **vptr 数量**   | 1 个                 | 多个（每个含虚函数的基类一个）                         |
| **虚表数量**      | 每类 1 张              | 派生类有多个虚表（每个基类一张）                        |
| **新增虚函数位置**   | 追加到唯一的虚表末尾          | 追加到第一张虚表（第一个基类）末尾                       |
| **指针赋值**      | 无偏移量调整              | 需要计算偏移量，指向对应的基类子对象                      |
| **this 指针调整** | 不需要                 | 通过 `thunk` 调整 this 指针                   |
| **调用路径**      | 对象 → vptr → 虚表 → 槽位 | 对象 → 对应基类的 vptr → 对应虚表 → 槽位 → thunk（如需） |
