# 生命周期、内存五区模型、动态内存

## 1. 生命周期 Lifetime

**生命周期**（Lifetime）指的是**变量或对象从创建（分配内存）到销毁（释放内存）的完整时间跨度**。

简单来说：**生命周期决定了一个变量能活（存在）多久。**

之前我们定义/声明的变量只能在其[[6. 分支、逻辑、关系运算符、作用域#5. 作用域 Scope|作用域]]内存活，离开其作用域就会死亡，例如：

```cpp
double global = 0.0; // 全局作用域

char* GetChar() // 函数作用域
{
	char ch = '\0'; // '\0' 是空字符
	return ch;
}

int main() // 函数作用域
{
	// 尝试让ptr指向GetChar返回的ch，这里的ptr是悬空指针，指向无效地址
	char* ptr = GetChar();
	
	if (true) // if 作用域
	{
		string life = "";
	}
	
	int count = 0; // 仅用来控制循环，不做演示
	while (1) // while 作用域
	{
		int i = 0;
		if (count++ > 2) break; // if
	}
}
```

以下的  i<sub>n</sub> 表示第 n 次循环的变量 i （也就是说每次循环结束 i 都死亡了，下次循环里是不同的 i）

|      流程      | global | ch  | ptr | life | i<sub>1</sub> | i<sub>2</sub> | i<sub>3</sub> |
| :----------: | :----: | :-: | :-: | :--: | :-----------: | :-----------: | :-----------: |
|     程序启动     |   存活   |     |     |      |               |               |               |
|  进入 main()   |   存活   |     |     |      |               |               |               |
| 进入 GetChar() |   存活   |     |     |      |               |               |               |
|  声明/初始化 ch   |   存活   | 存活  |     |      |               |               |               |
| 退出 GetChar() |   存活   | 死亡  |     |      |               |               |               |
|  声明/初始化 ptr  |   存活   |     | 存活  |      |               |               |               |
|    进入 if     |   存活   |     | 存活  |      |               |               |               |
| 声明/初始化 life  |   存活   |     | 存活  |  存活  |               |               |               |
|    退出 if     |   存活   |     | 存活  |  死亡  |               |               |               |
|    第一次循环     |   存活   |     | 存活  |      |      存活       |               |               |
|    第二次循环     |   存活   |     | 存活  |      |      死亡       |      存活       |               |
|    第三次循环     |   存活   |     | 存活  |      |               |      死亡       |      存活       |
|     循环结束     |   存活   |     | 存活  |      |               |               |      死亡       |
|  退出 main()   |   存活   |     | 死亡  |      |               |               |               |
|     程序结束     |   死亡   |     |     |      |               |               |               |

生命周期的更多概念我们会在此节课的剩余部分了解到。

## 2. 内存五区模型

### 2.1 内存五区模型的基本概念

**内存五区模型**是关于程序在运行时，**变量和数据在内存中如何布局、如何分配、如何访问**的底层规则。

简单来说，内存五区模型回答了三个问题：

1. **数据存在哪里？**（栈、堆、全局区、常量区、代码区）
2. **数据怎么存？**（连续、对齐、地址）
3. **数据什么时候创建和销毁？**（生命周期）

### 2.2 五大数据区域

```text
┌─────────────────────────────────────────────────────────────┐
│                      程序内存布局                             │
│  ┌─────────────────────────────────────────────────────┐    │
│  │                  代码区（Code）                       │    │
│  │              存放CPU执行的机器指令                     │    │
│  └─────────────────────────────────────────────────────┘    │
│  ┌─────────────────────────────────────────────────────┐    │
│  │                  常量区（Constant）                  │    │
│  │              存放字符串常量、const常量                 │    │
│  └─────────────────────────────────────────────────────┘    │
│  ┌─────────────────────────────────────────────────────┐    │
│  │                全局/静态区（Global/Static）           │    │
│  │              全局变量、static变量                     │    │
│  └─────────────────────────────────────────────────────┘    │
│  ┌─────────────────────────────────────────────────────┐    │
│  │                    堆区（Heap）                      │    │
│  │              动态分配的内存（new/delete）              │    │
│  │              由程序员手动管理                         │    │
│  └─────────────────────────────────────────────────────┘    │
│  ┌─────────────────────────────────────────────────────┐    │
│  │                    栈区（Stack）                     │    │
│  │              局部变量、函数参数、函数调用信息            │    │
│  │              由编译器自动管理                         │    │
│  └─────────────────────────────────────────────────────┘    │
└─────────────────────────────────────────────────────────────┘
```

### 2.2.1 栈区 Stack

| 属性       | 说明                        |
| -------- | ------------------------- |
| **存储内容** | 局部变量、函数参数、函数调用信息（返回地址、栈帧） |
| **管理方式** | **自动管理**（编译器自动分配和释放）      |
| **大小**   | 通常较小（几MB）                 |
| **速度**   | 极快                        |
| **生命周期** | 进入作用域时创建，离开作用域时销毁         |

```cpp
void Func() {
    int local = 10;        // 栈上分配
    double arr[100];       // 栈上分配
    // 离开 Func 时，local 和 arr 自动释放
}
```

我们之前创建的变量都存放在栈区，属于栈区变量。
因为栈区大小较小，所以开发时要避免因为在栈区声明的数据过大导致栈溢出（Stack Overflow）。

### 2.2.2 堆区 Heap

| 属性       | 说明                            |
| -------- | ----------------------------- |
| **存储内容** | 动态分配的数据（用`new` / `malloc` 分配） |
| **管理方式** | **手动管理**（程序员手动释放）             |
| **大小**   | 较大（几GB）                       |
| **速度**   | 较慢（需要操作系统介入）                  |
| **生命周期** | 从 `new` 到 `delete`，由程序员控制     |

```cpp
int* p = new int(10);   // 堆上分配
delete p;               // 手动释放
```

稍后我们会重点学习如何在堆区创建和管理数据。

>[!TIP] 概念：**分配** 和 **释放**
>**分配内存**（Allocate Memory）指的是：向操作系统申请一块空闲的内存空间，供程序使用。
>**释放内存**（Free / Deallocate Memory）指的是：把不再使用的内存归还给操作系统，让系统可以重新分配给其他程序使用。

### 2.2.3 全局/静态区 Global/Static

| 属性       | 说明                      |
| -------- | ----------------------- |
| **存储内容** | 全局变量、`static` 变量        |
| **管理方式** | **自动管理**（程序启动时分配，结束时释放） |
| **大小**   | 中等                      |
| **速度**   | 较快                      |
| **生命周期** | 程序启动 → 程序结束             |

```cpp
int global = 100;           // 全局变量（存放在全局/静态区）
static int staticVar = 50;  // 静态变量（存放在全局/静态区）
void Func() {
    static int count = 0;   // 函数内静态变量（也存放在全局/静态区）
    count++;
}
```

**全局作用域**在 `main` 函数外，定义/声明在全局作用域的变量即为**全局变量**，存储在全局/静态区。

`static` 变量即静态变量，是用 `static` 声明的变量，我们将在以后学到 `static` 说明符。

### 2.2.4 常量区 Constant

| 属性       | 说明                |
| -------- | ----------------- |
| **存储内容** | 字符串字面量、`const` 常量 |
| **管理方式** | 自动管理（只读）          |
| **特点**   | 只读，不能被修改          |

```cpp
const char* str = "Hello";   // "Hello" 存储在常量区
const int MAX = 100;         // 可能存储在常量区（取决于编译器优化）
```

### 2.2.5 代码区 Code

| 属性       | 说明                 |
| -------- | ------------------ |
| **存储内容** | 编译后的机器指令（函数的二进制代码） |
| **管理方式** | 自动管理（只读）           |
| **特点**   | 只读，防止程序意外修改自己的指令   |

## 3. 动态内存 Dynamic Memory

### 3.1 动态内存的基本概念

如果你要开发一个电话薄管理系统，管理手机里的电话，那么我们势必需要一个数组来存储电话：

```cpp
string telephones[length] = {};
```

那么问题来了，我们并不确定这个电话薄要存多少电话，这个数组应该定义成多长呢？我们当然能把 `length` 赋值为 `99999`，但是这样未免太浪费内存，而且还容易导致栈溢出。
不难发现，如果我们能让数组的长度任意改变，这个问题就迎刃而解了。而要想实现数组长度可以任意改变就需要**动态内存**。

**动态内存**（Dynamic Memory）指的是**在程序运行时，由程序员手动向操作系统申请和释放的内存**。它存储在**堆**（Heap）上，生命周期由程序员控制，不受作用域限制。

和栈内存对比：

| 对比   | 栈内存     | 堆内存（动态内存）          |
| ---- | ------- | ------------------ |
| 分配时机 | 编译时确定   | 运行时动态申请            |
| 管理方式 | 自动（编译器） | 手动（程序员）            |
| 生命周期 | 作用域内    | 手动控制（new → delete） |
| 大小   | 小（几MB）  | 大（几GB）             |
| 速度   | 快       | 较慢                 |

### 3.2 需要动态内存的部分场景

| 场景        | 说明               |
| --------- | ---------------- |
| **大小不确定** | 程序运行时才知道需要多大的内存  |
| **大小会变化** | 容器（数据结构）需要动态扩容   |
| **生命周期长** | 数据需要在函数调用结束后仍然存在 |
| **内存需求大** | 栈空间不够用，需要分配大块内存  |

### 3.3 用 new 运算符分配内存

`new` 是 C++ 中的**动态内存分配运算符**，用于在**堆**上分配内存，并**返回指向该内存的指针**。

简单来说：**`new` 就是向操作系统申请一块内存，并把这块内存的“门牌号”（地址）交给你。**

`new` 的使用方法：

| 用法          | 语法            | 说明              | 示例            |
| ----------- | ------------- | --------------- | ------------- |
| **分配单个变量**  | `new 类型`      | 分配一个未初始化的数据     | `new int`     |
| **分配并初始化**  | `new 类型(初始值)` | 分配并赋初值          | `new int(10)` |
| **分配数组**    | `new 类型[长度]`  | 分配连续多个数据        | `new int[5]`  |
| **分配并值初始化** | `new 类型()`    | 分配并初始化为 0（值初始化） | `new int()`   |

```cpp
// 1. 分配单个变量
int* p1 = new int;        // 分配未初始化的 int
int* p2 = new int(10);    // 分配并初始化为 10
int* p3 = new int();      // 分配并初始化为 0

// 2. 分配数组
int* arr1 = new int[5];   // 分配 5 个 int（未初始化）
int* arr2 = new int[5](); // 分配 5 个 int，全部初始化为 0
int* arr3 = new int[5]{1, 2, 3, 4, 5}; // C++11 列表初始化

// 3. 分配自定义类型
Student* s = new Student{"Alice", 18, 95.5};
```

执行 `new int(10)` 的底层行为：

1.  向操作系统申请 sizeof(int) 字节的内存（通常 4 字节）。
 2. 操作系统在堆上寻找空闲内存块。
 3. 如果找到，标记这块内存为“已占用”。
 4. 操作系统返回这块内存的起始地址给 C++ 的运行时库。
 5. 把 10 写入这块内存。
 6. C++运行时将地址赋值给指针并返回该指针。

```text
内存状态变化：

分配前：
┌────────────┬────────────┬────────────┬────────────┐
│  空闲       │  已占用     │  空闲      │  已占用     │
└────────────┴────────────┴────────────┴────────────┘

分配后：
┌────────────┬────────────┬────────────┬────────────┐
│  空闲       │  已占用     │  已占用(新) │  已占用     │
└────────────┴────────────┴────────────┴────────────┘
                              ↑
		                 返回这个地址
```

### 3.4 用 delete 运算符释放内存

`delete` 是 C++ 中的**动态内存释放运算符**，用于**释放 `new` 在堆上分配的内存**，将内存归还给操作系统。

简单来说：**`delete` 就是“把 `new` 借来的内存还回去”。**

`delete` 的用法：

| 形式            | 用途                   | 示例              |
| ------------- | -------------------- | --------------- |
| `delete 指针`   | 释放 `new` 分配的**单个数据** | `delete p;`     |
| `delete[] 指针` | 释放 `new[]` 分配的**数组** | `delete[] arr;` |

```cpp
// 释放单个数据
int* p = new int(10);
delete p;
p = nullptr; // 释放后立刻置空，防止悬空指针导致未定义行为


// 释放数组
int* arr = new int[5];
delete[] arr;
arr = nullptr; // 释放后立刻置空，防止悬空指针导致未定义行为

```

>[!WARNING] 注意
>1. 不要忘记释放堆区内存，否则会导致**内存泄漏**（Memory Leak）。
>2. `new` 对应 `delete`，`new[]` 对应 `delete[]`。混用会导致==**未定义行为**==！
>3. 避免指向被释放的内存，否则该指针会成为**悬空指针**，对其解引用会导致==**未定义行为**==！
>4. 避免释放已释放的内存，否则会导致==**未定义行为**==！
>5. 避免释放栈区内存，否则会导致==**未定义行为**==！

>[!TIP] 概念：**内存泄漏** Memory Leak
>**内存泄漏**（Memory Leak）是指：**程序在堆上分配了内存，但使用完毕后没有释放，导致这块内存既不能被程序继续使用，也无法被操作系统回收。**
>
>简单来说：**内存泄漏 = 借了不还。**
>
>|后果|说明|
|---|---|
|**内存逐渐耗尽**|程序越跑越慢，最终卡死或崩溃|
|**性能下降**|可用内存减少，系统频繁进行虚拟内存交换|
|**长时间运行的程序崩溃**|服务器程序、游戏等长时间运行的应用，会因内存耗尽而崩溃|
|**不可恢复**|泄漏的内存直到程序退出才会被操作系统回收|

### 3.5 悬空指针 Dangling Pointer

**悬空指针**（Dangling Pointer）是指**曾经指向有效内存地址，但该内存已被释放或销毁，指针仍然保留着那个地址**的指针。

简单来说：**悬空指针就是“拿着一个已经失效的门牌号”——门牌号本身还在，但房子已经被拆了。**

```cpp
int* p = new int(10);   // p 指向堆上的一块有效内存
delete p;               // 内存被释放
cout << *p;             // ❌ 悬空指针！p 仍然存储着已释放内存的地址
```

| 类型       | 定义             | 指针的值          | 示例                 |
| -------- | -------------- | ------------- | ------------------ |
| **野指针**  | 从未初始化，指向随机地址   | 随机值（不确定）      | `int* p;`          |
| **悬空指针** | 曾指向有效地址，但地址已失效 | 曾经有效的地址（但已失效） | `delete p;` 后的 `p` |

## 4. 野指针造成崩溃的原理

### 4.1 野指针的本质

在底层，指针就是一个**无符号整数**，存储的是**虚拟内存地址**。

```cpp
int* p;          // p 没有被初始化
```

此时，`p` 的值是**栈上原本残留的随机值**（比如 `0x7FFD_0000_1234`）。这个数字可能是：

- 一个**曾经有效但已失效的地址**
- 一个**从未被映射到物理内存的地址**
- 一个**属于其他变量的地址**

操作系统根本不认识这个“门牌号”，或者把它映射到了错误的地方。

### 4.2 读取野指针

当你执行 `int x = *p;` 时，CPU 会向内存管理单元（MMU）发送请求：

> **“我要读取虚拟地址 0x7FFD_0000_1234 处的 4 个字节。”**

MMU 会去查 **页表（Page Table）**——这是操作系统维护的一张映射表，记录“哪些虚拟地址对应哪些物理内存”。

| 页表查询结果              | 后果                                                                   |
| ------------------- | -------------------------------------------------------------------- |
| **该地址未映射到物理内存**     | CPU 触发 **\#PF（缺页异常）**，操作系统判断为非法访问 → 发送 **SIGSEGV（段错误）** → 程序崩溃。      |
| **该地址映射了，但不属于你的程序** | CPU 允许读写，但你在破坏其他程序或内核的数据。此时不崩溃，而是**悄悄破坏数据**，制造“潜伏性 Bug”。这是野指针最危险的情况。 |

### 4.3 写入野指针

写入操作比读取更危险，因为它会**直接修改物理内存**。

假设野指针 `p` 的值正好落在**栈上另一个变量 `b` 的地址**，那么执行 `*p = 100;` 时，实际上是在**覆盖 `b` 的值**。

```cpp
int main() {
    int b = 42;       // b 的地址是 0x1000
    int* p;           // p 未初始化，随机值恰好是 0x1000
    *p = 100;         // 实际修改了 b！ b 从 42 变成 100
}
```

此时程序不会立即崩溃，但后续使用 `b` 时，逻辑会出错（比如“用户输入了 42，却变成 100 了？”）。

这种 Bug 在大型项目中极难定位——因为错误发生在 `*p = 100`，而崩溃发生在几秒甚至很久后，堆栈里根本找不到野指针。

## 5. 指针注意事项·其二==（重点）==

### 5.1 避免指向函数返回的地址

返回的变量在函数返回后会被销毁，返回它的地址会导致**悬空指针**产生，可能导致==**未定义行为**==！

```cpp
int* Add(int a, int b)
{
	int sum = a + b;
	return &sum;
}

int main()
{
	int* ptr = Add(1, 1); // ❌ ptr为悬空指针，对其解引用会导致未定义行为
}
```

### 5.2 不要忘记释放堆区内存

忘记释放堆区内存会导致内存泄漏，例如：

```cpp
// 不断分配内存，导致内存泄漏
while(true)
{
	new int(0); // 每次循环分配 4 字节，但指针丢失，无法释放
}
```

### 5.3 释放后立刻置空指针

释放后立刻置空指针，防止悬空指针导致==**未定义行为**==！例如：

```cpp
int* ptr = new int(1);
delete ptr;
ptr = nullptr; // 立刻置空
```

### 5.4 避免释放已释放的内存

避免释放已释放的内存，否则会导致==**未定义行为**==！

```cpp
int* ptr = new int(0);
delete ptr;
delete ptr; // ❌ 重复释放，产生未定义行为
```

### 5.5 避免释放栈区内存

避免释放栈区内存，否则会导致==**未定义行为**==！

```cpp
int num = 10;
int* ptr = &num;
delete ptr;// ❌ 释放栈区内存，产生未定义行为
```

### 5.6 分配和释放类型要匹配

`new` 对应 `delete`，`new[]` 对应 `delete[]`。混用会导致==**未定义行为**==！

