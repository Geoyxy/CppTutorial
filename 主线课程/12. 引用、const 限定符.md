# 引用、const 限定符

## 1. 引用 Reference

### 1.1 引用的基本概念

**引用**（Reference）是 C++ 中一种**给变量起别名**的机制——它不创建新变量，而是让一个名字直接指向另一个已存在的变量。

简单来说：**引用就是“同一个东西的另一个名字”。**

### 1.2 引用的声明和初始化

语法：

```cpp
类型& 引用名 = 变量;
```

1. `类型` 必须是 `变量` 的类型。
2. 声明时就必须初始化。

例如：

```cpp
int a = 10;
int& ref = a;     // ref 是 a 的引用

double b = 3.14;
double& r = b;    // r 是 b 的引用

string s = "Hello";
string& str = s;  // str 是 s 的引用
```

初始化后的引用不能再重新绑定到其他变量：

```cpp
int a = 10;
int& ref = a;     // ref 是 a 的引用

int b = 20;
ref = b;          // 这实际是在通过引用 ref 把 b 赋值给 a，而非重新绑定
```

>[!WARNING] 引用的注意事项
>
| 注意事项         | 说明                        | 示例                              |
| ---------- | ------------------------- | ------------------------------- |
| **必须初始化**  | 引用在声明时必须绑定到一个变量           | `int& r;` ❌                     |
| **不能重新绑定** | 引用一旦绑定，不能再指向其他变量          | `r = b;` 只会把 b 的值赋给 r 指向的变量     |
| **类型必须匹配** | 引用的类型必须与被引用的变量类型一致        | `int& r = b;` ❌（`b` 是 `double`） |
| **没有空引用**  | 引用必须绑定到有效变量，不能为 `nullptr` | `int& r = nullptr;` ❌           |

### 1.3 变量名、指针、引用的底层原理

#### 1.3.1 变量名的底层原理

声明并初始化普通变量：

```cpp
int a = 42;
```

1. 编译器在栈上预留 4 字节（`sizeof(int)`）的空间。
2. 把数字 `42` 写入这块内存。
3. 在符号表中记录：变量名 `a` 对应地址 `0x1000`（假设）。
4. 此后，代码里出现变量名 `a`，编译器就把它替换成地址 `0x1000`。

因此，变量名实际是不占用内存的。

>[!NOTE] 概念：**符号表** Symbol Table
>**符号表**（Symbol Table）是编译器内部维护的一张“翻译对照表”，记录了**源代码中的名字（变量名、函数名、类型名等）** 和**底层地址/偏移量**之间的对应关系。
>
>简单来说：**符号表就是编译器用来“查名字对应哪个地址”的字典。**
>
>```text
>┌─────────────────────────────────────┐
│           符号表（Symbol Table）      │
├─────────────┬───────────────────────┤
│  名字（源码）  │  底层信息（地址/偏移量）│
├─────────────┼───────────────────────┤
│  a          │  栈偏移量：rbp-4        │
│  b          │  栈偏移量：rbp-8        │
│  global     │  地址：0x1000          │
│  Add        │  函数地址：0x2000       │
│  Student    │  类型信息              │
└─────────────┴───────────────────────┘
>```

^SymbolTable

通过变量名访问：`a = 100`

- 编译器翻译：把 100 写入地址 0x1000
- CPU 动作：找到 0x1000 这个门牌号，把里面的内容改成 100

#### 1.3.2 指针的底层原理

声明并初始化指针：

```cpp
int* p = &a;
```

1. 编译器在栈上预留 8 字节（`sizeof(int*)`，64 位系统）的空间（假设是 `0x2000`） ，用来存储一个地址。
2. 取 `a` 的地址（假设是 `0x1000`），把这个地址值 `0x1000` 写入这块内存 `0x2000` 。
3. 在符号表中记录：`p` 对应地址 `0x2000`。
4. 此后，代码里出现 `p`，编译器把它替换成地址 `0x2000`，这块内存里装着 `0x1000`。

通过指针访问：`*p = 100`

1. 编译器将 `*p` 翻译为：**“先读取 `p` 中存储的地址值，再向该地址写入数据”**。
2. CPU 执行：
	- ① 去地址 `0x2000` 读取内容，得到 `0x1000`（即 `a` 的地址）
	- ② 去地址 `0x1000`，把 `100` 写入该位置

#### 1.3.3 引用的底层原理

声明并初始化引用：

```cpp
int& r = a;
```

**情况一：当作“自动解引用的指针”处理（未优化/需要存储地址时）**

1. 编译器在栈上分配 8 字节（64 位系统）的空间（假设地址为 `0x2000`），用于存储 `a` 的地址。
2. 取 `a` 的地址（假设为 `0x1000`），写入 `0x2000` 这块内存。
3. 在符号表中记录：`r` 对应地址 `0x2000`。
4. 使用 `r` 时，编译器生成指令：先读取 `0x2000` 的内容（得到 `0x1000`），再访问该地址上的数据（即自动解引用）。

>在这种情况中，引用中底层类似一种**不能改变指向的指针**（即 const pointer， `类型* cosnt`），且这种指针可以**自动解引用**。

**情况二：作为纯别名被优化（编译器优化掉存储空间）**

1. 编译器在符号表中直接记录：引用名 `r` 就是变量 `a` 的别名，直接绑定到 `a` 的地址 `0x1000`。
2. 此后，代码中出现 `r` 时，编译器直接替换为地址 `0x1000`，就像使用 `a` 本身一样，不再为 `r` 分配额外的栈空间。

>在这种情况中，引用就单纯是变量的另一个名字（即别名）

> 总结：**引用在语法上是别名，在底层实现上通常是“自动解引用的指针”，但编译器可能直接优化掉引用，让它和原变量完全等价。**

>或者说：**引用**是一种底层行为更复杂的**语法糖**。

>[!NOTE] 语法糖 Syntactic Sugar
>**语法糖**（Syntactic Sugar）是指编程语言中**让代码更易读、更易写，但并没有引入新功能**的语法特性。
>
简单来说：**语法糖就是“更好的写法”——底层做的事情没变，但你写起来更舒服了。**
>
>之前接触过的语法糖：
>
>|语法糖|底层等价写法|作用|
|---|---|---|
|`a++` / `++a`|`a = a + 1`|自增|
|`a += 5`|`a = a + 5`|复合赋值|
|`arr[i]`|`*(arr + i)`|数组下标|
|`p->member`|`(*p).member`|指针成员访问|
|`for (int x : arr)`|`for (int i = 0; i < n; i++)`|范围 for 循环|
|`int& r = a;`|底层通常类似于const pointer，但实际行为更复杂|引用|
>
>语法糖的优缺点：
>
|优点|说明|
|---|---|
|**可读性高**|代码更接近自然语言，容易理解|
|**编写效率高**|减少冗余代码|
|**降低出错率**|减少手动操作的细节（如忘记 `*` 解引用）|
>
|缺点|说明|
|---|---|
|**可能隐藏复杂度**|你不知道底层在做什么（比如 `a++` 对迭代器可能涉及临时对象）|
|**可能影响性能**|某些语法糖（如后置 `++`）可能比底层写法慢|
|**新手可能混淆**|以为“引用就是别名，不占内存”，但底层其实可能存地址|

### 1.3 引用作为函数参数

之前在 [[8. 函数、return、参数、函数签名]] 中我们提到过参数有三种传递方式：

| 传递方式     | 说明                 | 能否修改实参 |
| -------- | ------------------ | ------ |
| **值传递**  | 将实参的**副本**传给形参     | ❌ 不能   |
| **引用传递** | 将实参的**引用**（别名）传给形参 | ✅ 能    |
| **指针传递** | 将实参的**地址**传给形参     | ✅ 能    |

引用传递和前面所学的指针传递一样，都可以修改实参。

```cpp
// 传值：修改的是副本，实参不变
void ChangeByValue(int x) {
    x = 100;
}

// 传指针：修改的是实参本身
void ChangeByPtr(int* x) {
	*x = 100;
}

// 传引用：修改的是实参本身
void ChangeByRef(int& x) {
    x = 100;
}

int main() {
    int a = 10;
    ChangeByValue(a);   // a 仍然是 10
    ChangeByPtr(&a);    // a 变为 100 （通过指针）
    ChangeByRef(a);     // a 变为 100 （通过引用）
    return 0;
}
```

实际上，引用传递和指针传递本质都是**地址传递**。这就是为什么两种传递方式都能修改实参。

### 1.4 引用作为返回值

函数可以返回引用类型，语法为：

```cpp
类型& 函数名(参数列表) {
    // 函数体
    return 变量;
}
```

`类型` 必须是 `变量` 的类型

这意味着函数返回的是**变量的引用**（即别名），而不是值的副本。

通常，我们称返回的引用为**左值**，返回的普通变量为**右值**

>[!NOTE] 概念：左值和右值 Lvalue & Rvalue
>**左值**（Lvalue）和**右值**（Rvalue）是 C++ 中表达式的两种分类，核心区别是：**表达式有没有一个“持久的地址”**。
>
>|概念|定义|能否取地址|能否放在 `=` 左边|
|---|---|---|---|
|**左值（Lvalue）**|有固定内存地址的表达式|✅ 能|✅ 能（通常）|
|**右值（Rvalue）**|没有固定地址的临时值|❌ 不能|❌ 不能|
>
>```cpp
int a = 10;    // a 是左值（有地址）
int b = a;     // a 是左值，此处隐式转换为右值，转换出的 10 是右值（没有地址）
int c = a + 5; // (a + 5) 是右值（临时结果）
>```
>
>左值和右值的对比：
>
>|对比维度|左值（Lvalue）|右值（Rvalue）|
|---|---|---|
|**有固定地址吗？**|✅ 有|❌ 没有|
|**能取地址（`&`）吗？**|✅ 能|❌ 不能|
|**能放在 `=` 左边吗？**|✅ 能（通常）|❌ 不能|
|**能放在 `=` 右边吗？**|✅ 能|✅ 能|
|**有名字吗？**|✅ 通常有|❌ 没有（临时值）|
|**例子**|`a`、`arr[0]`、`*p`|`10`、`a + b`、`GetValue()`|
|**生命周期**|长（由作用域决定）|短（表达式结束后销毁）|

^LvalueAndRvalue

>[!WARNING] 注意：避免返回悬空引用
>避免将函数内栈区的局部变量以引用返回，因为该函数结束后，该栈区局部变量被释放，引用悬空，使用此引用会导致==**未定义行为**==！
>```cpp
>int& GetValue() {
>    int x = 10;
>    return x;   // ❌ 危险！x 在函数返回后被释放，返回的引用悬空
>}
>```

### 1.5 链式调用 Chained Call （该小节有严重错误，移到OOP阶段）

对于 `string` 类型的变量，我们可以用成员访问运算符 `.` 来调用它的一个函数 `append`，这个函数的声明是：

```cpp
string& append(string right); // 返回值是引用，返回左值
```

例如：

```cpp
string str = "Hello,";
str.append(" World!");
cout << str; // 打印：Hello, World!
```

可以发现 `append` 函数可以在一个字符串（`.` 的左操作数）的末尾追加新的内容（实参），于是我们可以这样写：

```cpp
string str = "";
str.append("C").append("+").append("+");
cout << str; // 打印：C++
```

这里的 `str.append("C").append("+").append("+");` 就是链式调用。

**链式调用**（Chained Call）是指**在同一个表达式中连续调用多个函数**，前一个函数的返回值直接作为后一个函数的调用对象。

简单来说：**一条语句里，点（`.`）或箭头（`->`）连成一串。**

链式调用的条件是 `.` 的左操作数只能是左值，而不能是右值，例如如果函数 `append` 的声明改为：

```cpp
string append(string right); // 返回值是普通变量，返回右值
```

那么 `str.append("C").append("+").append("+");` 就会报错，因为不能对 `append` 返回的右值进行链式调用。

### 1.6 结构体和对象优先用引用或指针传递

对象类似于结构体变量，有若干个数据成员。

传递参数时，如果实参是结构体变量或对象，应该优先使用**引用传递**或**指针传递**。

因为一个结构体变量或对象有多个数据成员，值传递的拷贝特性（即拷贝出副本进行传递）会造成额外的性能开销。

## 2. const 限定符

### 2.1 const 的基本概念

在实际开发中，一个项目往往有错综复杂的变量及其行为，有时候我们希望有这样一个==**约定**==：
<p  style="text-align: center;">某个变量在程序中自始至终保持不变</p>
但实际上，我们可能因为代码的复杂性或其他原因而无意间违反这个约定，例如：

```cpp
#include <iostream>
using namespace std;

// 假设这是一个“按规矩不能改”的变量——系统配置中的最大连接数
int max_connections = 100;

// 一个“不小心”修改了它的函数
void ApplyConfig() {
    // 开发者的本意是“临时调整一下”，结果忘了改回来
    max_connections = 9999;
}

int main() {
    cout << "初始最大连接数：" << max_connections << endl;

    ApplyConfig();  // 某次调用后，值被悄悄改了

    cout << "调用 ApplyConfig() 后：" << max_connections << endl;

    // 后续代码还以为是 100，实际上已经是 9999 了
    // 整个系统的行为可能因此出错

    return 0;
}
```

输出：

```text
初始最大连接数：100
调用 ApplyConfig() 后：9999
```

问题：

1. `max_connections` 在程序中被“约定”为常量，但没有任何机制阻止它被修改。
2. `ApplyConfig` 在不知情的情况下（或程序员疏忽）修改了它。
3. 后续代码仍然以为它是 `100`，导致逻辑错误。
4. 编译器不会报错，因为语法上完全合法。

想解决这个问题，就得让编译器帮我们遵守这个约定，而实现这个功能，就需要用到 `const` 限定符。

`const` 是 C++ 中的一个**类型限定符**（Type Qualifier），用于**将变量或对象标记为“只读”**——一旦初始化后，它的值就不能再被修改。

简单来说：**`const` 就是给数据标记了“只读”。**

>[!TIP] 扩展
>`const` 来源于英语单词 **constant** 
>n.常量；常数
>adj. 恒定的；不断的；不变的；固定的；重复的；连续发生的

### 2.2 const 限定普通变量、结构体变量

`const` 无论修饰普通变量还是结构体变量时，**规则都完全一样**：都是把**变量本身**标记为只读，不能通过该变量名修改其内容（无论是单个值还是多个成员）。

修饰普通变量：

```cpp
const int MAX_SIZE = 100;
MAX_SIZE = 200;   // ❌ 错误！const 变量不能修改
```

特点：

1. 必须在**定义时初始化**。（这里指的是普通变量，而非成员变量）
2. 之后任何赋值操作都会触发编译错误。

修饰结构体变量：

```cpp
struct Student {
    string sno = "";
    string name = "";
    double score = 0.0;
};

const Student s1 = {"2024001", "Alice", 95.5};
s1.score = 100.0;   // ❌ 错误！结构体变量是 const，所有成员都只读
s1.name = "Bob";    // ❌ 错误！同上
```

特点：

1. 整个结构体变量是只读的，**所有成员都不能修改**。
2. 如果成员是数组，同样不能通过该变量名修改。

| 对比维度   | 普通变量                | 结构体变量                      |
| ------ | ------------------- | -------------------------- |
| 语法     | `const int a = 10;` | `const Student s = {...};` |
| 被保护的内容 | 变量的值                | 所有成员的值                     |
| 修改限制   | 不能重新赋值              | 不能修改任何成员                   |
| 初始化要求  | 必须初始化               | 必须初始化                      |
| 本质     | 变量只读                | 变量只读（成员只是变量的组成部分）          |

### 2.3 const 限定形参

`const` 修饰函数形参，表示**在函数体内部，该参数是只读的**，不能修改它的值，例如：

```cpp
// 值传递：保护形参（意义不大）
void Func(const int x) {
    x = 10;   // ❌ 错误！形参 x 是 const，不能修改
}
```

因为值传递中实参本就是副本，修改副本没有意义，所以`const` 修饰形参在值传递中意义不大，其意义更主要体现在**指针传递**和**引用传递**上。

```cpp
// 指针传递：保护指向的数据（不能修改实参）
void Func(const int* p) {
    // *p = 10;   // ❌ 错误！
}

// 引用传递：最常用，保护实参不被修改
void PrintStudent(const Student& s) {
    cout << s.name;   // ✅ 可以读取
    // s.score = 100; // ❌ 错误！
}
```

>[!WARNING] 注意：常量作为实参传递的陷阱
>对于非值传递，`const` 修饰的变量不能传给没被 `const` 修饰的形参，例如：
>```cpp
>void func(int& ref) {}
>
>int n = 10;
>int& normal_r = n;
>const int& const_r = n;
>
>func(normal_r); // ✅ 正确
>func(const_r); // ❌ 错误！const_r 作为常量不能传给非常量形参
>```

### 2.4 const 限定返回值

返回值如果是右值，一般不需要用 `const` 修饰：

```cpp
const int GetValue() {
    return 10;   // 返回 const int（很少用，因为返回的是临时值）
}
```

返回值是左值时，`const` 修饰返回值才更有意义：

```cpp
// 这里仅作示范，实际开发别这么写
const Student& GetStudent() {
    Student* ptr = new Student {"Alice", 18, 95.5};
    Student& ref = *ptr;
    return ref;   // 返回 const 引用，防止外部修改
}
```

### 2.5 const 限定指针

`const` 修饰指针分为一下三种情况：

| 写法                    |           读法           | `*p`（指向的数据） | `p`（指向的方向） |
| --------------------- | :--------------------: | :---------: | :--------: |
| `const int* p;`       |    pointer to const    |    ❌ 不能改    |    ✅ 能改    |
| `int* const p;`       |     const pointer      |    ✅ 能改     |   ❌ 不能改    |
| `const int* const p;` | const pointer to const |    ❌ 不能改    |   ❌ 不能改    |

|          英文读法          | 中文读法（仅供参考） |     C++ 专业术语     |
| :--------------------: | :--------: | :--------------: |
|    pointer to const    |  指向常量的指针   |   底层‑const 指针    |
|     const pointer      |    指针常量    |   顶层‑const 指针    |
| const pointer to const | 指向常量的指针常量  | 顶层 + 底层 const 指针 |


>[!NOTE] 说明

#### 2.5.1 pointer to const

```cpp
//两种写法
const int* p; // 更常见的写法
int const* p;
```

pointer to const 顾名思义就是其**指向的是常量**，对于 `const int* p = n` ，它的行为是：

1. 不能通过其修改指向的变量的值： `*p = 10; // ❌ 不能改指向变量的值`
2. 能修改其指向：`p = &a;`
3. （!注意!）其指向的变量能被直接修改： `n = 10;`

简单来说，pointer to const 是种“**只读指针**”（只能通过其读取指向变量，而不能修改指向变量）

#### 2.5.2 const pointer

```cpp
int* const p; // const pointer
```

const pointer 是**不能改变指向的指针**（即**指针自身是常量**），对于 `int* const p`,它的行为是：

1. 能通过其修改指向的变量的值：`*p = 10;`
2. 不能修改其指向：`p = &a; // ❌ 不能改指向

#### 2.5.3 const pointer to const

```cpp
const int* const p;
```

const pointer to const 合并了以上两种指针的特点：

1. 不能通过其修改指向的变量的值： `*p = 10; // ❌ 不能改指向变量的值`
2. 不能修改其指向：`p = &a; // ❌ 不能改指向`
3. 其指向的变量能被直接修改： `n = 10;`

### 2.6 cosnt 限定引用

与指针不同，`const` 修饰引用则只有**指向常量的引用**（reference to const， 常量引用），因为引用本身不能改变指向。

```cpp
const int& ref = n;
```

指向常量的引用的写法如下，其行为与 pointer to const  类似：

1. 不能通过引用改变指向的变量的值：`ref = 5; // ❌ 不能改指向变量的值`
2. 其指向的变量能被直接修改： `n = 10;`

### 2.7 const 限定数组

被 `const` 修饰的数组，其每个元素都不能被修改：

```cpp
const int arr[5]{};
arr[1] = 5; // ❌ 错误！数组被 const 修饰，不能修改其元素
```

没退化的普通数组是 const pointer `类型* const` ：

```cpp
int arr[5]{}; // arr 是 int* const
```

常量数组和普通数组作为实参时分别退化为 pointer to const  `const 类型*` 和普通指针：

```cpp
void func(int normal_arr[], const int const_arr[]) {...}

int normal_arr[5]{};
int const_arr[5]{};

func(normal_arr, const_arr)
{
	// normal_arr 退化为 int*（可修改元素）
	// const_arr 退化为 const int*（不可修改元素）
}
```

| 没退化的数组 | 没退化的数组                 | 退化后的数组           |
| ------ | ---------------------- | ---------------- |
| 普通数组   | const pointer          | pointer          |
| 常量数组   | const pointer to const | pointer to const |
