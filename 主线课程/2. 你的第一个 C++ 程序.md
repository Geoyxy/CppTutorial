## 2. 第一个代码

### 2.1 示范代码

```cpp
#include <iostream>
using namespace std;

int main()
{
	cout << "Hello, World!" << endl;
	
	return 0;
}
```

### 2.2 开始编程

> [!WARNING] **注意**：中 / 英文字符
> 在代码中，除了注释和字符串（这两者将在以后学到），**不应该出现中文字符**，比如 `我`, `；`, `《` 等，请在编写代码的过程中**确认你的输入法为英文模式**。
> 
> **尤其**是注意分号 `;` 不要写成中文的分号 `；`。
> 
> 另外，因为 `;` 和 `:` 在 VS 的编辑器中长得很像，所以**注意不要看错了**。

现在请在 VS 的文本编辑区（见 [[#1. 使用 VS 开始一个新项目]] 中第 12 步）中编写以上示范代码（如图）。

另外请注意， `{...}` 中的每行代码前面都有空格（即缩进），但这其实不是空格，而是制表符，要输入此制表符，请按下 `Tab`。（VS C++ 中 `Tab` 键默认输入的是制表符而非空格，你可以自行观察文本编辑区右下角的“制表符”字样）

![[hello world.png]]

如果你觉得代码的字体很小，请通过文本编辑区中左下角的百分比数字（图中红框圈出）自行调节。

编写完成后，请按 `F5`（如果你的键盘上有 `Fn` 键，你可能需要按 `Fn` + `F5`） 或点击文本编辑区上方的“本地 Windows 调试器”，过一会后应该弹出来一个黑色窗口（即控制台），其中写有 `Hello, World!`。

![[运行结果.png]]

如图，如果出现了错误，文本编辑区可能会立刻给你标注错误，错误列表中会显示错误的原因（要查看错误列表，请点击文本编辑区底部的“错误列表”）。

![[错误.png]]

图中的错误是把 `endl` 后的分号 `;` 写成了中文的分号 `；`。如果你遇到了错误，请先检查有没有地方用了中文的字符，或者没有在末尾加分号 `;`，如果实在没找出错误原因，请将你的错误代码复制给 AI 以寻求帮助。

### 2.3 尝试一些想法

现在你可能发现了，程序的输出结果——`Hello, World`，正是你在代码中写的 `"Hello, World"`。

现在，你可以尝试把 `cout << "Hello, World!" << endl;` 分别改为以下代码：

```cpp
cout << "Hello!";
```

```cpp
cout << "Hello," << endl << "World!";
```

```cpp
cout << "Hello,\n 世界!";
```

```cpp
cout << "我" << endl << "爱" << "\n" << "C++!";
```

### 2.4 编程规则

```cpp
#include <iostream>
using namespace std;

int main()
{
	// 在此处编写你的代码
	
	return 0;
}
```

在以后的编程中，将以上代码作为你编程的**模板**，即只在以上的 `// 在此处编写你的代码` 处编写你的代码。

> [!QUESTION] **问题**：这些代码是什么意思，我真的学会编程了吗？  
> 你目前不需要关注模板中代码的意思，以后你会在主线课程中依次学到，这么做是为了让你先从最基础的知识开始学起。如果你想修改以上模板，你应该明确知道你修改的理由。
> 
> 是的，你已经开始学会编程了。准确地说，你已经完成了编程中最重要的一步——**让计算机按照你的意图做事**。虽然你现在只会让它输出一句话，但这和以后让它计算复杂数据、处理图像、运行游戏，本质上是同一件事：你写下指令，计算机执行。
> 
> 所以，请先别急着否定自己。编程不是“背完所有语法才算会”，而是“能写出可运行的代码，并理解它为什么能运行”。你已经做到了第一点，第二点会随着课程推进慢慢补齐。

现在，你应该了解以下 C++ 的**语法规则**：

1. 所有**字符串**和**注释**（两者将在以后学到）以外的字符只能用英文字符。
2. 每条**语句**末尾都要加分号 `;`。模板代码中的 `#include`、`using`、`int main()`、`{ }` 不是语句，所以不加。
3. `int main()` 下的 `{...}` 内的末尾应该写 `return 0;` 即使你发现不写也没事。（想了解为什么？试试询问 AI）
4. `" "`, `[ ]`, `{ }`, `< >`, `( )` 这些符号应该成对出现（`<<`，`>>` 除外）。
5. 区分英文字母的大小写（这叫大小写敏感）。

> [!NOTE] **概念**：语法 Syntax
> **语法（Syntax）** 是一门编程语言规定的“合法写法”，管的是形式对不对，不管意思对不对。
> 
> 违反语法，程序会直接报错，运行不了；语法正确但意思不对，那就是后面要学的语义和逻辑问题了。

以及**代码风格**：

1. 分号 `;` 后一般是新的一行。
2. `{...}`中的代码前都有制表符。
3. `main()` 应该放在 `main.cpp` 文件中。
4. 代码文件的末尾一般应该有一个空行，例如（由于文章篇幅，我一般不会在课程内的其他代码块中的末尾加空行）：

```cpp
#include <iostream>
using namespace std;

int main()
{
	// 在此处编写你的代码
	
	return 0;
}

```

### 2.6 补充

以下旨在**为你补充编程概念**，让你更加专业。

1. 你按 `F5` 或 `Fn` + `F5` 后到出现控制台前的过程叫作“**构建并运行**”（但日常口语中我们会把它叫作“**编译**”，而编译实际上只是构建过程的一个步骤，你应当把它们区别开）。
2. 在以上过程（即构建过程）中工作的程序，我们日常把它们统称为“**编译器**”（但严格说它们不是同一个程序，它们分为“**链接器**”、“**调试器**”等。）
3. 构建过程中出现的错误，统称为**构建错误**。构建错误是由“编译器”、“链接器”等报出的，VS 的“错误列表”会把它们混在一起显示。日常我们一般会把“构建错误”叫成“编译错误”或“编译器报错”。
4. 你**试图**查找错误、定位原因并进行修改的过程，叫作**调试（Debug）**。调试的核心是“定位并修正程序行为与预期不符的地方”。**没有编译错误，不等于没有错误**。程序能跑但结果不对、崩溃、卡住，这些都属于需要调试的情况。
5. 编译错误 vs 运行时错误 vs 逻辑错误：
	- **编译错误**：代码不符合语法，编译器直接报错，程序根本生成不了。
	- **运行时错误**：程序能生成、能启动，但运行中崩溃，比如除以零、数组越界。
	- **逻辑错误**：程序能跑、不崩溃，但结果不对，比如算错了、输出错了。
	- 这三种里，**逻辑错误最难查**，因为编译器不会给你任何提示。
6. 你写的 `.cpp` 文件里的内容，叫作**源代码（Source Code）**，简称**源码**。它是给人看的文本，编译器要先把它构建成 `.exe` 文件（即可执行文件）才能运行。

> [!TIP] **提示**：学习心态  
>如果你发现以上概念有很多不懂，甚至感到疑惑，**这很正常，不必焦虑**。
>
>你才刚写出第一个 C++ 程序，而“构建”“编译”“链接”“调试”这些词，本来就要在后面的课程里慢慢展开。我提前放在这里，只是让你**先混个眼熟**，不是要你现在全懂。
>
>编程有个特点：**很多概念不是一次就能懂的，而是在反复使用中逐渐清晰**。第一遍模糊，第二遍有点感觉，第三遍用的时候才真正理解。这很正常。
>
>遇到不懂的地方，你可以：
>
>- **先跳过**，继续往下学，很多疑问后面会自然解开；
>- **记下来**，过几节再回头看，往往会有新理解；
>- **动手试**，改一改、跑一跑，比只看文字更容易懂；
>- **问 AI**，问具体哪里不懂，而不是“我全都不懂怎么办”。
>
>但别因为一个概念不懂就停下来死磕。初学阶段最重要的是先让程序跑起来，先建立起“我能写代码”的信心。很多概念，写久了自然就懂了。
>
> 你现在能让控制台里出现 `Hello, World!`，这就已经是一个真正的开始了。剩下的，慢慢来。
