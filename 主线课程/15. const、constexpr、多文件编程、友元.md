# const、constexpr、多文件编程、友元

## 1. const 限定成员函数

被 `const` 限定的成员函数叫作 `const` 成员函数，它承诺：**该函数不会修改对象的数据成员**。

在成员函数的参数列表后加上 `const` 限定符即可声明为 `const` 成员函数。

例如：

```cpp
class Person
{
private:
    string name_;
    int age_;

public:
    // 非 const 成员函数：可以修改数据成员
    void SetName(const string& name)
    {
        name_ = name;  // ✅ 可以修改
    }

    // const 成员函数：承诺不修改数据成员
    string GetName() const
    {
        return name_;  // ✅ 只读取，不修改
        // age_ = 10;  // ❌ 错误！const 函数不能修改成员
    }
};
```

const 和非 const 版本的成员函数可以**共存**，构成**重载**。编译器会根据对象是否是 `const` 来决定调用哪个版本。例如：

```cpp
class Array
{
private:
    int data_[10];

public:
    // 非 const 版本：返回可修改的引用
    int& operator[](int index)
    {
        return data_[index];
    }

    // const 版本：返回只读的引用
    const int& operator[](int index) const
    {
        return data_[index];
    }
};

int main()
{
    Array arr;
    arr[0] = 10;        // ✅ 调用非 const 版本

    const Array& const_arr = arr;
    // const_arr[0] = 20; // ❌ const 对象只能调用 const 版本
    int value = const_arr[0]; // ✅ 调用 const 版本

    return 0;
}
```

## 2. constexpr 说明符

### 2.1 constexpr 的基本概念

`constexpr`（**const expression** 的缩写）是 C++11 引入的**说明符（Specifier）**，它告诉编译器：**"这个值可以在编译期确定"**。

简单来说：`const` 是"运行时只读"，`constexpr` 是"编译期常量"。

| 关键字         | 含义       | 何时确定值 |
| ----------- | -------- | ----- |
| `const`     | 只读（不能修改） | 运行时   |
| `constexpr` | 编译期常量    | 编译时   |

```cpp
int x = 10;
const int a = x;        // ✅ 只读，但运行时才确定值
constexpr int b = 10;   // ✅ 编译期确定
// constexpr int c = x; // ❌ 错误！x 不是编译期常量
```

### 2.2 constexpr 常量

 constexpr 常量必须满足以下条件：

1. **类型必须是字面类型（Literal Type）**：基本类型（`int`、`double`、`char` 等）都是字面类型。
2. **初始化值必须是编译期常量**：不能用运行时才能确定的值来初始化。

例如：

```cpp
constexpr int kSize = 10;        // ✅ 字面量初始化
constexpr int kHalf = kSize / 2; // ✅ 用 constexpr 变量初始化
constexpr int kLength = 5 + 3;   // ✅ 编译期计算

int value = 20;
constexpr int kBad = value;    // ❌ 错误！value 不是编译期常量
```

>[!TIP] 提示：constexpr 常量的命名风格
>对于 constexpr 常量：
>
>1. 若该常量为函数内的局部常量，则命名风格推荐 snake_case，例如：`local_value`
>2. 若该常量为其他种类的常量，则命名风格推荐 kPascalCase，例如：`kMaxStudent`

必须使用 constexpr 常量的场景：

| 场景                     | 示例                                              | 为什么必须用                       |
| ---------------------- | ----------------------------------------------- | ---------------------------- |
| **数组大小**（C-style 数组）   | `int arr[kMaxSize];`                            | 数组大小必须在编译时确定                 |
| **模板参数**（非类型模板参数）      | `std::array<int, kBufferSize>`                  | 模板参数必须是编译期常量                 |
| **枚举值初始化**             | `enum { SIZE = kBufferSize };`                  | 枚举值必须是常量表达式                  |
| **`static_assert` 断言** | `static_assert(kMaxSize > 0, "Size must > 0");` | 断言条件必须在编译时求值                 |
| **`constexpr` 函数的参数**  | `Square(kMyConstant)`                           | 如果参数不是 `constexpr`，则无法在编译期计算 |
| **位域（Bit-field）大小**    | `int flags : kFlagBits;`                        | 位域大小必须是编译期常量                 |

推荐使用 constexpr 常量的场景：

|场景|示例|推荐理由|
|---|---|---|
|**全局/命名空间中的数值常量**|`constexpr double kPi = 3.14159;`|明确这是编译期常量，可读性高|
|**类中的静态整型常量**|`static constexpr int kMaxConnections = 100;`|编译期常量，不会占用对象内存（C++17 前无需类外定义）|
|**配置参数（阈值、最大值等）**|`constexpr int kTimeoutMs = 5000;`|表明这些值永远不会变，且编译时确定|
|**数学/物理常量**|`constexpr double kGravity = 9.8;`|纯计算值，适合编译期优化|
|**性能敏感的边界值**|`constexpr size_t kCacheLine = 64;`|避免运行时读取，编译器可直接优化|
|**`switch` 的 `case` 标签**|`case kMaxSize:`|`case` 标签必须是常量表达式（用 `constexpr` 保证）|
|**函数内的局部“常量”**|`constexpr int local_limit = compute();`|明确该值在编译时已确定（需 `compute` 也是 `constexpr`）|

> [!WARNING] **注意**：编译期常量的数据成员
> 如果对一个数据成员使用 `constexpr` 说明符，则应该同时使用 `static` 说明符，例如：
> 
> ```cpp
> class A {
> 	static constexpr int kMaxValue = 10;
> };
> ```
> 
> 关于 `static` 说明符，我们将在 [[17. static 说明符、命名空间、枚举#1. static 说明符|17-1 static 说明符]] 学习。

### 2.3 constexpr 函数

`constexpr` 函数是指**可以在编译期求值的函数**。如果函数的参数是编译期常量，函数的结果也会在编译期计算出来。

constexpr 函数的规则（C++11）：

| 规则         | 说明                            |
| ---------- | ----------------------------- |
| **函数体**    | 只能有一条 `return` 语句（C++11）      |
| **参数和返回值** | 必须是字面类型                       |
| **递归**     | 允许，但深度有限制                     |
| **调用**     | 传编译期常量 → 编译期求值；传运行时变量 → 运行时求值 |

C++14/17/20 逐步放宽了限制：允许在函数体内使用循环、局部变量等。

```cpp
// constexpr 函数：平方
constexpr int Square(int x)
{
    return x * x;
}

// constexpr 函数：阶乘
constexpr int Factorial(int n)
{
    return (n <= 1) ? 1 : n * Factorial(n - 1);
}

int main()
{
    // 编译期计算
    constexpr int result1 = Square(5);    // ✅ 25，编译期确定
    constexpr int result2 = Factorial(5); // ✅ 120，编译期确定

    // 运行时计算（也可以，constexpr 函数兼容运行时）
    int x = 10;
    int result3 = Square(x);              // ✅ 运行时计算，返回 100

    // 编译期常量可以用在需要常量的地方
    int arr[Square(4)];                   // ✅ 16 个元素的数组

    return 0;
}
```

### 2.4 constexpr 成员函数

类中的成员函数也可以标记为 `constexpr`。这意味着该函数可以在编译期对对象进行操作。

```cpp
class Point
{
private:
    double x_;
    double y_;

public:
    // constexpr 构造函数：可以在编译期构造对象
    constexpr Point(double x, double y) : x_(x), y_(y) {}

    // constexpr 成员函数：可以在编译期调用
    constexpr double GetX() const { return x_; }
    constexpr double GetY() const { return y_; }

    // constexpr 函数：计算距离平方
    constexpr double DistanceSquared(const Point& other) const
    {
        double dx = x_ - other.x_;
        double dy = y_ - other.y_;
        return dx * dx + dy * dy;
    }
};

int main()
{
    // 编译期构造对象
    constexpr Point p1(3.0, 4.0);
    constexpr Point p2(0.0, 0.0);

    // 编译期计算距离平方
    constexpr double dist = p1.DistanceSquared(p2);  // ✅ 25
    // static_assert(dist == 25.0, "dist should be 25"); // 编译期断言

    return 0;
}
```

## 3. 多文件编程

### 3.1 多文件编程的基本概念

到目前为止，我们所有的代码都写在一个 `.cpp` 文件里。这种方式在学习阶段没问题，但在实际项目中会面临严重问题：

|问题|说明|
|---|---|
|**代码臃肿**|成千上万行代码挤在一个文件里，难以阅读和维护|
|**编译缓慢**|每次修改任何一行代码，整个项目都要重新编译|
|**协作困难**|多人同时修改同一个文件，冲突不断|
|**逻辑混乱**|所有功能混在一起，没有模块划分|

**解决方案**：多文件编程——把代码按照功能拆分成多个文件。

多文件编程主要涉及两种文件：

| 文件类型    | 后缀（文件扩展名）      | 作用              | 内容            |
| ------- | -------------- | --------------- | ------------- |
| **头文件** | `.h` / `.hpp`  | 声明（Declaration） | 类声明、函数声明、常量、宏 |
| **源文件** | `.cpp` / `.cc` | 定义（Definition）  | 函数实现、成员函数实现   |

例如：

```text
项目结构：
my_project/
├── main.cpp          # 主程序入口
├── person.h          # Person 类的声明
├── person.cpp        # Person 类的实现
└── utils.h           # 工具函数声明
```

>[!TIP] 文件的命名风格
>1. 文件名建议不要使用中文、空格、`!@#$%^&*()` 等特殊字符。
>2. 不要混用大小写，Windows 大小写不敏感、Linux 大小写敏感，跨平台会出问题。（大小写敏感的意思是区分大小写）
>3. 命名风格：（本教程依旧推荐谷歌规范：snake_case）
>
>|风格|示例|使用场景|
|---|---|---|
|**PascalCase**|`MyGameEngine`, `StudentSystem`|Qt、Windows MFC、老 VS 项目|
|**snake_case**|`my_game_engine`, `student_system`|Linux、CMake、Google 规范|
|**kebab-case**|`my-game-engine`|开源仓库文档、少量库|
>
>4. **通常一个文件一个类**，这时类名应该和文件名对应，例如：
>
>|类名|头文件|源文件|
|---|---|---|
|`Person`|`person.h`|`person.cpp`|
|`StudentManager`|`student_manager.h`|`student_manager.cpp`|
|`NetworkUtils`|`network_utils.h`|`network_utils.cpp`|
|`FileReader`|`file_reader.h`|`file_reader.cpp`|

>具体如何在 VS 中多文件编程将在 [[### 3.5 多文件编程实践]] 学习，如果你 3.2 - 3.4 没看懂，也可以先看 3.5 。在 3.5 中发现不懂的地方时，再回头在 3.2 - 3.4 查找。

### 3.2 头文件 Header File (.h)

**头文件只放声明，不放定义**（有少量例外）：

1. 类的声明/定义（成员变量 + 成员函数声明）
2. 函数声明（原型）
3. 常量声明（`constexpr`、`const`）
4. 类型别名（`using`、`typedef`）
5. 宏定义（`#define`，尽量少用）
6. 模板定义（模板必须在头文件中定义）

例如：

```cpp
// person.h
#pragma once

#include <string>
using namespace std; // 这里的 using namespace std 仅作演示使用，实践中不推荐

extern int global_value; // 普通全局变量

// 类的声明
class Person
{
private:
    string name_;
    int age_;

public:
	static int s_count; // 静态变量
    Person(const string& name, int age);
    void SetName(const string& name);
    string GetName() const;
    void Print() const;
};
```

头文件中的普通全局变量应该用 `extern` 说明。

头文件中仅允许初始化以下对象：

1. constexpr 常量
2. inline 变量 （C++17）

>[!WARNING] 注意：不应该在头文件中使用 `using namespace std`
>在头文件中使用 `using namespace std` 会污染其他文件的全局命名空间，关于“命名空间”和 `using namespace` 我们会在 [[17. static 说明符、命名空间、枚举#2. 命名空间|17-2. 命名空间]] 学到。

当多个文件包含同一个头文件时，可能导致重复定义的编译错误。有两种解决方法：

1. 头文件守卫（Include Guard）

格式：

```cpp
// 文件名：file_name.h
#ifndef FILE_NAME
#define FILE_NAME

// 头文件内容

#endif
```

例如：

```cpp
// 文件名：my_class.h
#ifndef MY_CLASS
#define MY_CLASS

class MyClass { ... };

#endif
```

这种方式是 C++ 标准支持的方式。

>[!TIP] 提示：宏的命名风格
>以上代码中的 `FILE_NAME`, `MY_CLASS` 是**宏**（Macro），宏的命名风格推荐为 UPPER_SNAKE_CASE，规则为：
>
>1. 所有字母大写。
>2. 单词间用下划线 `_` 连接。
>   
>例如：`MAX_BUFFER_SIZE`

2. `#pragma once`

格式：

```cpp
// 文件名：my_class.h
#pragma once

// 头文件内容
```

`#pragma once` 虽然不属于 C++ 标准，但是 MSVC、Clang、GCC 等所有主流编译器都支持的这种指令。它告诉编译器"这个文件只包含一次"。

默认情况下， VS 在 Windows 平台使用的编译器是 MSVC 。

>[!QUESTION] **问题**：为什么叫头文件？
>在 C 语言（C++ 的前身）诞生的早期，编译器是**单遍编译（Single-pass Compilation）**的——编译器从头到尾只读一遍源代码，不会回头查找。
>
>这就产生了一个问题：如果函数 `B` 调用了函数 `A`，但 `A` 的定义写在 `B` 的**后面**，编译器读到 `B` 时还不知道 `A` 的存在，就会报错。
>
>**解决方案**：把所有函数、类型、变量的**声明**提前写在文件的**最开头**（头部）。这样编译器在往下读之前，就已经知道了所有东西的存在。
>
>```cpp
>// ===== 头部的声明 =====
>int Add(int a, int b);   // 告诉编译器：有个函数叫 Add
>class Person;            // 告诉编译器：有个类叫 Person
>extern int global_value; // 告诉编译器：有个全局变量
>// ===== 后面的实现 =====
>int Add(int a, int b) {
>    return a + b;
>}
>```
>
>后来，这些“放在文件头部的东西”越来越多，人们干脆把它们单独拆出来放在一个文件里——这就是**头文件（Header File）**的起源。

### 3.3 源文件 Source File (.cpp)

**源文件放定义（实现）**。

源文件的推荐包含顺序：

1. **对应的头文件**（如 `person.cpp` 对应 `person.h`）
2. 标准库头文件（`<iostream>`, `<string>` 等）
3. 第三方库头文件
4. 项目内其他头文件

包含自己写的头文件时应该用 `""` 而非 `<>` 包围头文件名字，且自己写的头文件应该带扩展名 ".h" 。

若要实现/定义头文件中类的成员，则应该在成员的标识符前加 `类名::` 。

```cpp
// person.cpp
#include "person.h"
#include <iostream>
using namespace std;

int global_value = 0; // 全局普通变量的定义（初始化）

int Person::s_count = 0; // 成员变量的定义（初始化）

// 成员函数的定义（实现）
Person::Person(const string& name, int age)
    : name_(name), age_(age) {}

void Person::SetName(const string& name)
{
    name_ = name;
}

string Person::GetName() const
{
    return name_;
}

void Person::Print() const
{
    cout << name_ << " (" << age_ << "岁)" << endl;
}
```

>[!QUESTION] **问题**：头/源文件应该分别包含哪些标准库头文件
>每个文件只包含自己需要的标准库头文件，但如果源文件需要的标准库头文件 `<a>` 已在对应头文件包含，则源文件不需要再包含 `<a>`，例如：
>
>```cpp
>// test.h
>#pragma once
>#include <string>
>
>void PrintStr(const std::string& str); // 这里只需要 <string>
>```
>
>```cpp
>// test.cpp
>#include "test.h"
>#include <iostream> // 因为 test.h 已经包含了 <string> 所有这里不再包含 <string>
>
>// 这里需要包含 <string> 和 <iostream>
>void PrintStr(const std::string& str)
>{
>	std::cout << str;
>}
>```

>[!QUESTION] **问题**：为什么叫“源文件”？
>因为它是**程序的源头**——程序员手写的、人类可读的原始文本文件，是程序的**“原始材料”**，经过编译器加工后才会变成机器能执行的程序。


### 3.4 主源文件 (main.cpp)

**`main.cpp` 只应该做“启动”这一件事**。它不应该包含复杂的类实现，更不应该写具体的业务逻辑（比如计算分数的代码）。

>[!NOTE] 概念：业务 Business Logic
>**业务（Business Logic）** 指的是**程序要解决的实际问题领域中的规则和操作**，而不是程序本身的技术实现细节。
>
>简单来说：**业务 = “程序在真实世界中要做什么”**。
>
>|场景|业务逻辑（做什么）|技术实现（怎么写）|
|---|---|---|
|学生系统|学生入学、计算平均分、升级|`Student` 类、`CalculateAverage()` 函数|
|银行系统|存钱、取钱、转账、查询余额|`BankAccount` 类、`Deposit()`、`Withdraw()`|
|游戏|玩家攻击、掉血、升级、死亡|`Player` 类、`TakeDamage()`、`LevelUp()`|
|电商|下单、支付、库存扣减|`Order` 类、`Pay()`、`ReduceStock()`|
>
>例如：
>
>```cpp
>// ✅ 这是业务逻辑：描述“玩家承受伤害”这个游戏规则
>void Player::TakeDamage(double damage) {
>    double actual_damage = damage - defence_;
>    if (actual_damage < 0) actual_damage = 0;
>    hp_ -= actual_damage;
>    if (hp_ <= 0) Die();  // 血量归零则死亡
>}
>
>// ❌ 这不是业务逻辑，这是实现细节：打印日志、调试信息
>void Player::TakeDamage(double damage) {
>    cout << "[DEBUG] 进入 TakeDamage，damage = " << damage << endl;  // 调试代码
>    // ...
>}
>```

`main.cpp` 的核心职责是：**创建对象、调用接口、启动程序流程。**

你可以把它想象成电影里的“导演”：它不负责具体的表演（那是演员`Person`的事），也不负责写剧本（那是`person.cpp`的事），它只负责喊“开始”和“停”。

**`main.cpp` 的内容，按顺序主要包括：**

1. **必要的头文件**：包含你需要使用的类的声明（`person.h`）。
2. **程序入口**：`int main()` 函数。
3. **简单的逻辑**：在 `main` 函数内部，创建对象，调用成员函数，控制程序流程（如循环、条件判断）。

例如：

```cpp
// main.cpp
#include <iostream>     // 如果要用 cout
#include "person.h"     // 包含自己写的 Person 类

int main() {
    // 1. 创建对象
    Person p1("Closure", 30);
    Person p2("Amiya", 14);

    // 2. 调用成员函数，测试功能
    p1.Print();
    p2.Print();

    // 3. 简单的流程控制
    p1.SetName("New Name");
    std::cout << "修改后的名字: " << p1.GetName() << std::endl;

    // 4. 返回 0，告诉系统程序正常结束
    return 0;
}
```

## 4. 友元 Friend

### 4.1 友元的基本概念

封装（`private`/`protected`）的目的是**隐藏内部实现细节**。但在某些场景下，完全隐藏会带来不便：

|场景|问题|友元的解决方案|
|---|---|---|
|**全局运算符重载**|`operator<<` 需要访问私有成员来打印对象|声明为友元，允许访问|
|**两个类紧密协作**|一个类需要直接操作另一个类的内部状态|声明友元类，简化接口|
|**工具函数**|某个全局函数需要访问类的内部数据|声明为友元函数|

这时我们就需要友元来打破封装。

**友元**（Friend）是 C++ 的一种访问授权机制，**打破类的封装**，允许一个外部函数 / 另一个类，访问本类所有成员（包括 `private`、`protected` 私有成员）。

>[!WARNING] 注意：友元的使用
>实际开发中，尽量不要使用友元，友元的合理使用场景较少（比如重载运算符），具体可以根据所属项目的规范使用友元。

### 4.2 友元函数 Friend Function

在类内部用 `friend` 关键字声明一个外部函数，这个函数就可以访问该类的私有成员。

例如：

```cpp
class Person {
private:
    string name_;
    int age_;

public:
    Person(const string& name, int age) : name_(name), age_(age) {}

    // 声明友元函数：这个函数可以访问 Person 的私有成员
    friend void PrintPerson(const Person& p);
};

// 友元函数的定义（在类外部）
void PrintPerson(const Person& p) {
    // ✅ 可以访问私有成员
    cout << p.name_ << " (" << p.age_ << "岁)" << endl;
}

int main() {
    Person p("Alice", 25);
    PrintPerson(p);  // 输出：Alice (25岁)
    return 0;
}
```

注意：

1. 友元函数**不是成员函数**（它没有 `this` 指针）。
2. 友元函数在类外定义，和普通函数一样。
3. 声明位置（`public`/`private`）不影响友元权限——它始终能访问私有成员。

### 4.3 友元类 Friend Class

一个类也可以声明另一个类为友元。友元类的**所有成员函数**都可以访问本类的私有成员。

```cpp
// 发动机类
class Engine {
private:
    int horsepower_; // 马力
    int cylinders_;  // 气缸数量

public:
    Engine(int hp, int cyl) : horsepower_(hp), cylinders_(cyl) {}

    // 声明 Car 为友元类
    friend class Car;
};

class Car {
private:
    string brand_;   // 品牌
    Engine engine_;  // Car 拥有 Engine

public:
    Car(const string& brand, int hp, int cyl)
        : brand_(brand), engine_(hp, cyl) {}

    void ShowEngineInfo() const {
        // ✅ Car 可以访问 Engine 的私有成员
        cout << brand_ << " 的引擎："
             << engine_.horsepower_ << " 马力，"
             << engine_.cylinders_ << " 缸" << endl;
    }
};

int main() {
    Car my_car("BYD", 190, 4);
    my_car.ShowEngineInfo();
    return 0;
}
```
