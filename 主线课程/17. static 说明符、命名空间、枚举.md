# static 说明符、命名空间、枚举

---

## 1. static 说明符

### 1.1 static 说明符的概念

`static` 说明符是一种**存储类说明符 (storage-class-specifier)**。它的具体含义取决于它**出现在哪里**：

| 使用场景                  | 作用                             | 关注者     |
| --------------------- | ------------------------------ | ------- |
| **全局作用域中的 `static` ** | 将实体限制为**内部链接**（只在当前文件可见）       | 链接器     |
| **局部作用域中的 `static` ** | 将变量的生命周期延长到**整个程序运行期间**（静态存储期） | 运行时     |
| **类中的 `static` **     | 将成员变为**属于类本身**（而非属于对象）         | 编译器和运行时 |

### 1.2 全局作用域中的 static

在全局作用域（函数外部）使用 `static`，会将该实体（变量或函数）的链接属性从默认的**外部链接**改为**内部链接**。

```cpp
// file1.cpp
static int g_count = 0;      // 内部链接：只在 file1.cpp 中可见
static void Helper() {}      // 内部链接：只在 file1.cpp 中可见

// file2.cpp
static int g_count = 0;      // 完全独立的另一个变量，不冲突
static void Helper() {}      // 完全独立的另一个函数，不冲突
```

**效果**：每个 `.cpp` 文件都有自己的 `g_count` 和 `Helper`，互不干扰。

**与普通全局变量的对比**：

|写法|链接属性|是否跨文件可见|不同文件同名会冲突吗|
|---|---|---|---|
| `int g_count = 0;` |外部链接|✅ 能|✅ 会（重复定义错误）|
| `static int g_count = 0;` |内部链接|❌ 不能|❌ 不会（各自独立）|

>[!WARNING] 注意：头文件中**不建议**使用 `static`
>头文件中**不建议**使用 `static` 定义全局变量，因为每个包含该头文件的 `.cpp` 都会获得一份独立的副本，这在大多数情况下不是你想要的，而且会让“共享变量”的意图变得模糊。

>[!TIP] 提示：`static` 的**推荐替代**
>匿名命名空间（`namespace { ... }`）是 `static` 的现代替代方案，**功能相同但更推荐**。
>
>关于命名空间，我们将在下一个章节下学到。

### 1.3 局部作用域中的 static

函数内被 `static` 说明的变量称为**静态局部变量**，它的**存储期**：从**自动存储期**（栈）变为**静态存储期**（静态存储区）。

>[!NOTE] **概念**：静态存储期 Static Storage Duration
>具有**静态存储期**的变量，其内存在**程序启动时分配**，在**程序结束时释放**，整个运行期间都存活。
>
>常见的静态存储期变量：
>
>|变量类型|示例|说明|
|---|---|---|
|**全局变量**（非 `static`）| `int g_count;` |默认外部链接，程序启动时分配，结束时释放|
|**全局 `static` 变量**| `static int s_count;` |内部链接，存储期同样是静态的|
|**局部 `static` 变量**| `static int count = 0;` |函数内声明，第一次执行到该行时初始化，之后一直存活|
|** `constexpr` 全局常量**| `constexpr int kSize = 10;` |编译期常量，存储期也是静态的（但通常优化为直接嵌入代码）|
|**字符串字面量**| `"Hello"` |存储在常量区，也是静态存储期|

**关键行为**：

1. 变量在**程序启动时**分配内存，在**程序结束时**销毁。
2. 变量**只初始化一次**（第一次执行到声明时初始化）。
3. 变量在函数调用之间**保持其值**。

```cpp
void Counter() {
    static int count = 0;   // 只初始化一次，后续调用保留值
    count++;
    std::cout << "count = " << count << std::endl;
}

int main() {
    Counter();   // 输出：count = 1
    Counter();   // 输出：count = 2
    Counter();   // 输出：count = 3
    return 0;
}
```

**与普通局部变量的对比**：

| 写法                      | 存储期      | 初始化时机  | 函数调用间是否保留值 |
| ----------------------- | -------- | ------ | ---------- |
| `int count = 0;`        | 自动存储期（栈） | 每次函数调用 | ❌ 不保留      |
| `static int count = 0;` | 静态存储期    | 仅第一次调用 | ✅ 保留       |

> [!NOTE] **概念**：翻译单元（Translation Unit）
> **翻译单元**是 C++ 编译过程的**基本单位**。它是编译器在一次编译中处理的**所有代码的集合**。
> 
> 简单来说：**一个 `.cpp` 文件 + 它通过 `#include` 包含的所有头文件 = 一个翻译单元**。
> 
> ```text
> main.cpp
>     ├── #include "person.h"   → 展开 person.h 的全部内容
> 	│   ├── #include <string>   → 展开 string 的全部内容
> 	│   └── class Person { ... };
>     ├── #include <iostream>   → 展开 iostream 的全部内容
>     └── int main() { ... }
> 
> 以上所有内容合并在一起，称为一个“翻译单元”。
> ```

> [!WARNING] **注意**：
>1. 静态局部变量是**线程不安全**的（C++11 起，其初始化是线程安全的，但读写仍需要同步）（不知道多线程的话这里过目即可）。
>2. 使用全局变量时，要注意跨翻译单元的初始化顺序不确定；使用局部静态变量时，要注意它的初始化表达式不能依赖其他编译单元中可能尚未初始化的全局变量。因此建议：==**避免使用全局变量**==，例如：
>   
>```cpp
>// ========== common.h ==========
>#pragma once
>struct A {
>    int val;
>    A();      // 构造函数在 .cpp 中定义
>};
>extern A g_a; // 声明在其他编译单元定义的全局对象
>void F();     // 声明包含静态局部变量的函数
>
>// ========== a.cpp ==========
>#include "common.h"
>#include <iostream>
>
>A::A() : val(42) { // 全局对象的构造函数
>    std::cout << "g_a constructed\n";
>}
>
>A g_a; // 定义全局对象（动态初始化）
>
>// ========== b.cpp ==========
>#include "common.h"
>#include <iostream>
>
> void F() {
>    static int local = g_a.val; // ⚠️ 静态局部变量初始化时引用其他单元的全局对象
>    std::cout << "local = " << local << "\n";
>}
>
>struct B {
>    B() {
>        std::cout << "g_b constructor\n";
>        F(); // 构造函数中调用 F，触发 local 的初始化
>    }
>};
> B g_b;         // 另一个全局对象，初始化顺序与 g_a 不确定
>```
>
>以上代码中，有两个翻译单元 I, II。II 中的 `g_b` 的初始化依赖 I 中的 `g_a`（即  `g_b` 的初始值由 `g_a` 决定）。运行期开始，若 II 比 I 先执行，此时 `g_b` 因为访问未被初始化的值（或未被分配的内存）而导致==**未定义行为**==。
>
>这个问题也叫作“静态初始化顺序惨案 static initialization order fiasco” 或 “不同翻译单元初始化顺序未指定 initialization order between different translation‑units is unspecified”，要解决此问题，可以：
>
>3. 将全局变量改为 `constexpr` 常量，这样运行前就已经初始化，防止依赖未初始化的值。
>4. 将全局变量改为**局部静态变量**，这样全局变量可以被使用时就初始化，例如：
>
>```cpp
>// ========== common.h ==========
>#pragma once
>#include <iostream>
>
>struct A {
>    int val;
>    A();
>};
>A& GetA(); // 返回全局单例
>void F();
>
>// ========== a.cpp ==========
>#include "common.h"
>
>A::A() : val(42) { // 全局对象的构造函数
>    std::cout << "g_a constructed\n";
>}
>
>// 用函数封装全局对象，代替直接暴露全局变量
>A& GetA() {
>    static A instance;   // 第一次调用时初始化
>    return instance;
>}
>
>// ========== b.cpp ==========
>#include "common.h"
>#include <iostream>
>
> void F() {
>    // 通过 GetA() 访问 A，保证 A 已经初始化
>    static int local = GetA().val;
>    std::cout << "local = " << local << "\n";
>}
>
>struct B {
>    B() {
>        std::cout << "B constructor\n";
>        F();  // 调用 F()，触发 GetA() 的初始化
>    }
>};
>
> B g_b;   // 全局对象，但不再依赖其他全局对象的初始化顺序
>```

### 1.4 类中的 static（静态成员）

在类中被 `static` 说明的成员为**静态成员**，静态成员属于**类本身**，而不是属于类的某个对象。

#### 1.4.1 静态数据成员

```cpp
class Person {
public:
    static int s_count;   // 声明：静态成员，属于类，不属于对象
    std::string name_;
    explicit Person(const string& name) : name_(name) {}
};

int Person::s_count = 0;   // 定义：必须在类外定义（C++17 前）
Person p1("Tom");
Person::s_count++;
Person p2("Bob");
Person::s_count++;
cout << "当前人数：" << Person::s_count; // 打印：当前人数：2

p1.s_count = 5; // ⚠️ 警告：不推荐通过对象访问静态成员
```

**关键行为**：

1. 所有对象**共享**同一个 `s_count`（而不是每个对象有一份）。
2. 访问静态数据成员时标识符需要 `类名::` 前缀（不需要对象）。
3. 必须在 `.cpp` （类外）中**定义**一次（分配内存），不能在头文件（类中）中定义（除非用 `inline`）。

**C++17 起，可以用 `static inline` 直接在类内定义**：

```cpp
class Person {
public:
    static inline int s_count = 0;   // ✅ C++17 起，直接在类内定义
};
```

**与普通成员变量的对比**：

| 写法                    | 属于对象还是类 | 内存分配   | 访问方式                       |
| --------------------- | ------- | ------ | -------------------------- |
| `int age_;`           | 每个对象    | 每个对象一份 | 需要通过对象访问（`p.age_`）         |
| `static int s_count;` | 类本身     | 全局一份   | 可通过类名访问（`Person::s_count`） |

>[!TIP] **提示**：静态数据成员的**命名风格**
>对于静态数据成员：
>
>1. 若没有被 `constexpr` 说明，命名风格为 `s_ + snake_case + _`，例如：`s_instance_count_`
>2. 否则命名风格为 `constexpr` 常量的命名风格 `kPascalCase`，例如：`kMaxAge`

#### 1.4.2 静态成员函数

```cpp
class Person {
private:
    static inline int s_count_ = 0;
    std::string name_;

public:
    static int GetCount() {   // 静态成员函数
        return s_count_;      // ✅ 可以访问静态成员
        // return name_;      // ❌ 错误：不能访问非静态成员（没有 this）
    }
};

Person::s_count = 1; // ✅ 通过 Person:: 访问
Person::GetCount();  // ✅ 通过 Person:: 访问

Person p1;
p1.GetCount();       // ⚠️ 警告：不推荐通过对象访问静态成员
```

**关键行为**：

1. **没有 `this` 指针**，因此不能访问非静态成员。
2. 可以通过 `Person::GetCount()` 调用，不需要对象。

>[!WARNING] **注意**：不推荐通过对象访问静态成员
>C++ 确实允许通过对象来访问静态成员（无论是静态数据成员还是静态成员函数）：
>
> ```cpp
> Person p1;
> p1.GetCount();       // ✅ 语法上允许
> int count = p1.s_count_;   // ✅ 语法上也允许（但如果 s_count_ 是 private，在外部就不能访问）
> ```
>
>编译器会把 `p1.GetCount()` 处理成 `Person::GetCount()`，不会报错，但会导致一些问题：
>
>|问题|说明|
|---|---|
|**误导性**|看起来像是“访问了对象 p 1 的成员”，但静态成员其实不属于 p 1，而是属于整个类|
|**破坏可读性**|阅读代码的人会误以为 `GetCount()` 访问或修改了 `p1` 的状态|

## 2. 命名空间 Namespace

### 2.1 命名空间的基本概念

回顾一下，为了确定一个标识符的可见范围，我们之前学了：

| 概念        | 决定者 | 作用范围    | 典型控制方式                                      |
| --------- | --- | ------- | ------------------------------------------- |
| **作用域**   | 编译器 | 源代码文本区域 | `{}`                                        |
| **链接属性**  | 链接器 | 目标文件之间  | `static`, `extern`, `inline`, `const`（默认内部） |
| **访问说明符** | 编译器 | 类的内外    | `public`, `private`, `protected`            |
| **存储期**   | 运行时 | 内存存活时间  | `static`（局部）, `new`, `auto`（默认）             |

命名空间也是用于确定一个标识符的可见范围的，它通过类似“分组隔离”的方式，将不同标识符分配到不同的“组”，并在访问标识符时从指定的“组”寻找。

![[逻辑上标识符可见性.jpg]]

命名空间作为一种“逻辑容器”和文件的区别：

| 概念       | 作用            | 维度     |
| -------- | ------------- | ------ |
| **文件**   | 物理组织代码（在哪里存）  | 磁盘上的位置 |
| **命名空间** | 逻辑组织名字（属于哪一组） | 代码中的分组 |

### 2.2 命名空间的定义

命名空间只能在“**全局作用域**”或“**其他命名空间的作用域**”内定义，这也说明着，命名空间可以**嵌套**。

定义语法：

```cpp
namespace 命名空间名 
{
	// 实体（如变量、函数、类、其他命名空间...）
}
```

需要注意：

1. 命名空间只能在“**全局作用域**”或“**其他命名空间的作用域**”内定义。
2. 命名空间可以**嵌套**。
3. 命名空间可以多处定义。
4. 为 `std` 命名空间添加声明或定义，除非是特化标准模板况，否则==**行为未定义**==。

例如：

```cpp
// 全局作用域
namespace Math {
    int max(int a, int b) {
        return (a > b) ? a : b;
    }
    const double PI = 3.14159;
}

namespace Game {
    int max(int a, int b) {
        return (a > b) ? a : b;
    }
    int fps = 60;
    
    // 嵌套命名空间
    namespace Character {
	    int max(int a, int b) {
	        return (a > b) ? a : b;
	    }
	    int damage = 100;
    }
}

namespace Math {
    const double e = 2.71828;
}
```

>[!TIP] **提示**：命名空间的命名风格
>命名空间的命名风格推荐用 `snake_case` ，且推荐用**项目名**或**文件路径**命名。例如有个项目的目录树为：
>
> ```text
> my_project/              # 项目名
> ├── core/
> │   ├── engine/          # 引擎核心
> │   ├── events/          # 事件系统
> │   └── memory/          # 内存管理
> ├── model/
> │   ├── entities/        # 游戏实体（Player, Enemy）
> │   └── components/      # 组件（Health, Position）
> ├── renderer/
> │   ├── shaders/         # 着色器
> │   └── textures/        # 纹理
> └── utils/
>     ├── math/            # 数学库
>     ├── io/              # 文件IO
>     └── logging/         # 日志
> ```
>
>命名空间：
>
> ```cpp
> // ===== core/engine/component.h =====
> namespace my_project {
>	namespace core {
>		namespace engine {
>			class Component { ... }
>		}
>	}
> }
>
> // ===== model/entities/player.h =====
> namespace my_project {
>	namespace model {
>		namespace entities {
>			class Player { ... }
>		}
>	}
> }
> ```

### 2.3 :: 运算符

`::` 是 C++ 中的**作用域解析运算符（scope resolution operator）**，它用于**指定某个标识符所属的作用域或命名空间**。

按有无左操作数， `::` 有两种写法

1. 有左操作数

```cpp
左操作数::右操作数
```

- 左操作数：命名空间名 / 类名 / 枚举名（必须是一个类型或命名空间）
- 右操作数：标识符 

其中 `左操作数::右操作数` 也叫做**限定名（qualified-id）**

例如：

```cpp
namespace my_project {
	class Main {
		public:
		~Main() = default;
		static void func() { ... };
	}
}

my_project::Main::func();  // 调用 func 函数
my_project::Main::~Main(); // Main 类的析构函数
```

2. 无左操作数

```cpp
::右操作数
```

这个时候 `::` **左边是空，没有左操作数**，语法上它是**一元形式**，不是二元。

`::右操作数` 访问的是全局作用域下的标识符，例如：

```cpp
// 全局作用域
int val = 0;

int main() {
	int val = 1;
	cout << ::val; // 打印 0 
	cout << val;   // 打印 1
}
```

如此就能解决局部作用域对全局作用域的名子隐藏。

>[!TIP] **提示**：回顾“**名字隐藏**”
> 若不熟悉“**名字隐藏**”，请回顾 [[6. 分支、逻辑、关系运算符、作用域#5. 作用域 Scope|6-5. 作用域]] 。

>[!TIP] **提示**：嵌套命名空间定义 （C++ 17）
>C++ 17 起支持用 `::` 进行**嵌套命名空间定义（Nested Namespace Definition）**，例如：
>
> ```cpp
> // ===== core/engine/component.h =====
> namespace my_project::core::engine {
>	class Component { ... }
> }
>
> // ===== model/entities/player.h =====
> namespace my_project::model::entities {
>	class Player { ... }
> }
> ```
>
>|注意点|说明|
|---|---|
|**所有中间命名空间必须已经存在**| `my_project` 和 `my_project::core` 必须在之前已经定义过，否则编译报错|
|**C++17 起才支持**|如果编译器使用 C++14 或更早标准，需要改用传统嵌套写法|

### 2.4 命名空间别名 Namespace Alias 

在之前的代码示例我们可以观察到命名空间的名字（限定名）通常较长，这个时候我们可以使用命名空间别名。

语法：

```cpp
namespace 别名 = 原命名空间名;
```

例如：

```cpp
namespace very_long_namespace_name {
    void Print() { std::cout << "Hello\n"; }
}

// 起别名
namespace short = very_long_namespace_name;

int main() {
    short::Print();   // 等价于 very_long_namespace_name::Print()
    return 0;
}
```

>[!WARNING] **注意**：不要在头文件中定义别名
>建议**不要在头文件中定义别名**，因为**头文件中定义别名会污染所有包含它的文件**，容易引起冲突。推荐在源文件或函数内部定义别名。

### 2.5 using 指令 using-directive 

`using` 是一种**声明关键字**，它可以用作 `using` 指令。

`using` 指令是 C++ 中**将命名空间中的所有名称引入当前作用域**的机制。

语法：

```cpp
using namespace 命名空间名;
```

**作用**：将 `命名空间` 中的所有标识符“暴露”到当前作用域，之后可以直接使用它们，而无需加 `命名空间名::` 前缀。

例如： `cout`, `cin`, `endl`, `string` 等标识符是标准命名空间 `std` 下的标识符，但我们使用了 `using namespace std;`  后，就不用在这些标识符前加 `std::` 前缀了：

```cpp
#include <iostream>
#include <vector>
#include <string>

// 不使用 using 指令
int main() {
    std::cout << "Hello\n"; // 每次都要写 std::
    std::vector<int> vec;
    std::string name = "Alice";
    return 0;
}

// 使用 using 指令，将 std 中所有名称引入当前作用域
int main() {
    using namespace std;    // 直接写
    cout << "Hello\n";
    vector<int> vec;
    string name = "Alice";
    return 0;
}
```

`using` 指令会导致两个问题：

1. 若当前作用域内有同名标识符则**隐藏** `using namespace` 引入的标识符：

```cpp
namespace A {
    void Print() { cout << "A\n"; }
}

void Print() { cout << "Global\n"; }

int main() {
    using namespace A;
    Print();      // 输出 "Global"（当前作用域的 Print 优先）
    A::Print();   // 输出 "A"（明确指定）
    return 0;
}
```

2. 若两个引入的命名空间有同名标识符，会因为**二义性（ambiguity）** 而报错：

```cpp
namespace A { void Print() { cout << "A\n"; } }
namespace B { void Print() { cout << "B\n"; } }

int main() {
    using namespace A;
    using namespace B;
    Print();    // ❌ 编译错误：不明确，是 A::Print 还是 B::Print？
    A::Print(); // ✅ 明确指定用 A 的
    B::Print(); // ✅ 明确指定用 B 的
    return 0;
}
```

>[!WARNING] **注意**：`using` 指令的使用场景
>1. 在头文件中使用 `using namespace` 是 C++ 社区公认的**不良实践**，它会污染所有包含该头文件的文件的全局命名空间。
>2. 在源文件中**谨慎（推荐避免）**使用 `using namespace std;`，除非编程竞赛中追求速度。

> [!TIP] **提示**：关于 `using namespace std`
> 学完本小节之后就不应该继续在练习中使用 `using namespace std` 了，相反，应该手动为之前接触过的 `cout`, `cin`, `endl`, `string`, `getline` 加 `std::` 前缀。  

### 2.6 using 声明 using-declaration

`using` 是一种**声明关键字**，它也可以用作 `using` 声明。

`using` 声明是 C++ 中**将命名空间中的某个特定标识符引入当前作用域**的机制，让你可以**不用再写 `::` 前缀**就能使用它。

语法：

```cpp
using 命名空间名::标识符;
```

例如：

```cpp
#include <iostream>

int main() {
    // 不用 using，每次都要写 std:: 
    std::cout << "Hello ";
    std::cout << "World!" << std::endl;

    // 用 using 声明，引入 cout 和 endl
    using std::cout;
    using std::endl;
    
    cout << "Hello ";         // 不用再写 std:: 前缀
    cout << "World!" << endl; // 不用再写 std:: 前缀
    
    return 0;
}
```

“`using` 声明”与“`using` 指令”的对比

| 对比维度 | `using` 声明         | `using` 指令             |
| ---- | ------------------ | ---------------------- |
| 语法   | `using std::cout;` | `using namespace std;` |
| 引入范围 | **单个**标识符          | **整个命名空间**的所有标识符       |
| 污染风险 | ✅ 低（只引入需要的）        | ❌ 高（可能引入大量不想要的名称）      |
| 推荐场景 | ✅ **推荐**           | ⚠️ 谨慎使用（尤其在头文件中）       |

`using` 指令会导致的两个问题（名字隐藏和二义性）在 `using` 声明中依然存在，这里不在赘述。

>[!WARNING] **注意**：避免在头文件中使用 `using` 声明
>仍然建议**不要在头文件中使用 `using` 声明**，因为包含该头文件的所有文件都会被“污染”。

### 2.7 匿名命名空间 Anonymous Namespace

**匿名命名空间**是 C++ 中一种**没有名称**的命名空间。它用于将实体（变量、函数、类等）**限制在当前翻译单元（`.cpp` 文件）内可见**，是实现**内部链接**的一种方式。

例如：

```cpp
// 匿名命名空间
namespace {
    // 这里的实体只在当前翻译单元内可见
    int internal_count = 0;
    void Helper() { /* ... */ }
    class InternalClass { /* ... */ };
}

void PublicFunction() {
    s_count++; // 可以直接使用，无需 ::
    Helper();  // 可以直接使用，无需 ::
}
```

| 作用              | 说明                                             |
| --------------- | ---------------------------------------------- |
| **替代 `static`** | 在全局作用域中，`static` 也能实现内部链接，但匿名命名空间是 C++ 推荐的现代方式 |
| **防止命名冲突**      | 不同翻译单元中的匿名命名空间内的同名实体互不干扰                       |
| **封装实现细节**      | 将“仅供当前文件内部使用”的辅助函数、工具类等隐藏起来，不暴露给其他文件           |

> [!WARNING] **注意**：不建议头文件中使用匿名命名空间
> **不建议头文件中使用匿名命名空间**，因为如果在头文件中定义匿名命名空间，每个包含该头文件的 `.cpp` 都会获得**一份独立的副本**：
> ```cpp
> // ===== bad.h =====
> #pragma once
> namespace {
>     int count = 0;   // 每个 .cpp 各有一份 count
> }
> 
> // ===== a.cpp =====
> #include "bad.h"
> void FuncA() { count++; }  // 修改的是 a.cpp 中的 count
> 
> // ===== b.cpp =====
> #include "bad.h"
> void FuncB() { count++; }  // 修改的是 b.cpp 中的 count，与 a.cpp 无关
> ```
> 
> 虽然能在两个 `.cpp` 中“正常访问”，但它们的 `count` 是**完全独立**的。这种行为可能造成误解，因此**头文件中不应该使用匿名命名空间**，它在头文件中没有意义。

## 3. 枚举 Enumeration

### 3.1 枚举的基本概念

你是否写过类似以下的代码？

```cpp
class Character {
private:
	// 物品栏，不同的值代表不同的物品
	// 0：空
	// 1：泥土
	// 2：圆石
	// ...
	int inventory[30]{};
}
```

这段代码虽然能工作，但存在几个**严重问题**：

| 问题        | 说明                                            |
| --------- | --------------------------------------------- |
| **可读性差**  | 一眼看去 `inventory[0] = 1`，根本不知道 `1` 代表什么        |
| **维护困难**  | 如果新增物品，需要记住所有数字的含义，很容易出错                      |
| **类型不安全** | `inventory[0] = 999` 可以编译通过，但 `999` 是无效的物品 ID |
| **调试困难**  | 调试时看到的是数字 `1`、`2`、`3`，而不是有意义的名称               |

**解决方案**：用枚举来给这些“**魔法数字（magic number）**”起一个有意义的名字。

>[!NOTE] **概念**：魔法数字 Magic Number
>**魔法数字**：代码中直接出现、没有任何解释命名的**字面常量（裸数字）**，读者无法一眼看懂这个数字代表什么含义。
>
>例如：
>
> ```cpp
> // 看不懂 60、1000 是什么含义
> int delay = 60 * 1000;
> if (score >= 60)
> ```
>
> `60`、`1000` 就是魔法数字。别人阅读代码时会疑惑：为什么是 60？代表分钟？及格线？

**枚举**（Enumeration）是 C++ 中的一种**用户自定义类型**，用于定义一组**命名的整型常量**。它的主要作用是**让代码更可读、更安全**。

简单来说：**枚举就是把一组相关的常量值，用有意义的名字来表示。**

C++ 中有两种枚举：

| 枚举类型                      | 引入版本  | 作用域          | 底层类型         | 隐式转换     |
| ------------------------- | ----- | ------------ | ------------ | -------- |
| **无作用域枚举** (`enum`)       | C++98 | 枚举名暴露在外层作用域  | 整型（由编译器选择）   | 会隐式转换为整型 |
| **有作用域枚举** (`enum class`) | C++11 | 枚举名限定在枚举作用域内 | 默认 `int`，可指定 | 不会隐式转换   |

### 3.2 无作用域枚举 Unscoped Enumeration

无作用域枚举也叫**普通枚举**。

#### 3.2.1 无作用域枚举的定义

定义语法：

```cpp
enum 枚举类型 [: 底层类型] {
	枚举成员1 [= 枚举值1],
	枚举成员2 [= 枚举值2],
	枚举成员3 [= 枚举值3],
	...
	枚举成员k [= 枚举值k],
	...
	枚举成员n [= 枚举值n]
};
```

枚举成员也叫**枚举器（enumerator）**。

**规则**（不用现在看懂，接下来会逐条说明）：

1. `[...]` 表示 `[]` 中的内容可不写。
2. `枚举类型`, `枚举成员` 为标识符，`底层类型` 必须是整型（包括 `char`），`枚举值` 必须是**编译期常量表达式**。
3. 若不写 `= 枚举值1`，则 `枚举成员1` 的枚举值为 `0`。
4. 若不写 `= 枚举值k`，则 `枚举成员k` 的枚举值为 `枚举成员k-1的枚举值 + 1`。
5. 若不写 `: 底层类型`，编译器自动选能够表示所有枚举值的整数类型为 `底层类型` ，通常选 `int`。
6. `枚举值` 可以**隐式类型转换**为 `底层类型`。

> [!TIP] **提示**：命名风格（两种枚举都适用）
> |命名对象|命名风格|示例|
> |---|---|---|
> |**枚举类型**| `PascalCase` | `enum UrlTableErrors { ... };` |
> |**枚举成员** - **推荐**| `k` + `PascalCase` | `kOk = 0, kErrorOutOfMemory` |
> |**枚举成员** - **可选**| `UPPER_SNAKE_CASE` | `OK = 0, ERROR_OUT_OF_MEMORY` |

规则 1：`[...]` 表示 `[]` 中的内容可不写。
规则 2：`枚举类型`, `枚举成员` 为标识符，`底层类型` 必须是整型（包括 `char`），`枚举值` 必须是**编译期常量表达式**。

```cpp
enum Color : char { // 底层类型为整型(char)
	kRed,           // 可选择不写 [] 内的内容
	kYellow = 3,    // 编译期常量表达式
	kBlue = '2'     // 编译期常量表达式
};
```

规则 3：若不写 `= 枚举值1`，则 `枚举成员1` 的枚举值为 `0`。
规则 4：若不写 `= 枚举值k`，则 `枚举成员k` 的枚举值为 `枚举成员k-1的枚举值 + 1`。

```cpp
enum Color {
	kRed,     // 枚举值：0
	kYellow,  // 枚举值（= 0 + 1）：1
	kBlue     // 枚举值（= 1 + 1）2
};
```

规则 5：若不写 `: 底层类型`，编译器自动选能够表示所有枚举值的整数类型为 `底层类型` ，通常选 `int`。
规则 6：`枚举值` 可以**隐式类型转换**为 `底层类型`。

```cpp
enum Color {  // 假设这里编译器选的底层类型为 int
	kRed,
	kYellow,
	kBlue
};

// 这里看不懂可以先看下一小节
int val = kBlue; // kBlue 的枚举值隐式转换为 int 类型，val = 2
```

> [!TIP] **提示**：分文件中的枚举
> 若你在分文件中使用枚举，建议你将枚举的实现也放在头文件中。

#### 3.2.2 无作用域枚举的使用

定义 / 声明并初始化 无作用域枚举的对象的语法：

```cpp
枚举类型 枚举类型的对象 = 枚举成员;
```

例如：

```cpp
// 物品枚举
enum Item : int {
	kCopper, // 铜
	kIron,   // 铁
	kGold,   // 金
	kDiamond // 钻石
};

int main() {
	Item item = kIron; // 定义枚举类型的对象 item
	Item inventory[3]{kCopper, kIron, kGold}; // 物品栏
	return 0;
}
```

枚举值可以隐式转为其对应的底层类型（规则 6）：

```cpp
int num1 = kIron;      // num1 = 1
// kCopper的枚举值 → int → double
double num2 = kCopper; // num2 = 0.0
```

> [!WARNING] **注意**：谨慎使用无作用域枚举
> 在现代 C++ 中，**应该谨慎使用无作用域枚举**，原因主要有两个：
> 
> 1. **名称污染**（枚举成员暴露在外层作用域）
> 2. **类型不安全**（会隐式转换为整型）
> 
> 在大型项目中，这两点可能导致难以追踪的 bug。
> 
> 1. 无作用域枚举的枚举成员是暴露在外层作用域（即定义该枚举类型的作用域）中的，这导致两个相同作用域的无作用域枚举不能有相同的枚举类型：
> 
> ```cpp
> enum Color { kRed, kGreen, kBlue };
> enum TrafficLight { kRed, kYellow, kGreen };  // ❌ 错误！kRed、kGreen 重复定义
> ```
> 
> 2. **类型不安全**：
> 
> ```cpp
> enum Color { kRed, kGreen, kBlue };
> enum Status { kOk, kError, kPending };
> 
> Color c = kGreen;
> Status s = kError;
> 
> if (c == s) {  // ✅ 编译通过，但逻辑无意义！（比较 Color 和 Status）
>     // 这里会被执行，因为两者的值都是 1
> }
> ```
>   
> 这种代码可以编译通过，但完全是逻辑错误。
> 
> **推荐使用有作用域枚举。**

无作用域枚举枚举的**前向声明（forward declaration）** 的语法：

```cpp
// 声明
enum 枚举类型 : 底层类型T;
// 定义
enum 枚举类型 [: 底层类型T] { ... };
```

**规则**：

1. 前向声明时**必须**为声明指定底层类型。
2. 前向声明后，定义中可以不指定底层类型。
3. 若定义中也指定底层类型，且声明和定义的底层类型不一致，则出现==**未定义行为**==。

例如：

```cpp
// ===== forward.h =====
#pragma once
// 前向声明（必须指定底层类型）
enum Color : int;
void PrintColor(Color c);  // 可以在声明中使用该类型

// ===== forward.cpp =====
#include "forward.h"
// 定义（可以省略底层类型，但必须与声明一致）
enum Color : int {
    kRed = 0,
    kGreen = 1,
    kBlue = 2
};

void PrintColor(Color c) {
    // ...
}
```


### 3.3 有作用域枚举 scoped Enumeration

有作用域枚举是 C++11 引入的**更安全**的枚举类型，它解决了无作用域枚举的两个核心问题：**名称污染**和**类型不安全**。

有作用域枚举也叫**强类型枚举（strongly-typed enumeration）**。

有作用域枚举的定义和使用与无作用域枚举类似，因此这里不再细分章节。

```cpp
// 定义
enum class 枚举类型 [: 底层类型] {
	枚举成员1 [= 枚举值1],
	枚举成员2 [= 枚举值2],
	枚举成员3 [= 枚举值3],
	...
	枚举成员k [= 枚举值k],
	...
	枚举成员n [= 枚举值n]
};
```

**规则**：

1. `enum class` 关键字也可以用 `enum struct`，二者等价。
2. `底层类型` 默认为 `int`，可显式指定其他整型。
3. 枚举成员**不会**暴露到外层作用域。
4. 枚举值**不存在**隐式类型转换。

有作用域枚举可以前向声明，而且通常不需要指定底层类型（因为它默认是 `int`），但仍需保证**声明与定义的底层类型必须一致**，例如：

```cpp
// ===== forward.h =====
#pragma once
// 前向声明（不需要指定底层类型）
enum class Color;

// ===== forward.cpp =====
#include "forward.h"
// 定义（可以省略底层类型，但必须与声明一致）
enum class Color {
    kRed = 0,
    kGreen = 1,
    kBlue = 2
};
```

定义 / 声明并初始化 有作用域枚举的对象的语法：

```cpp
枚举类型 枚举类型的对象 = 枚举类型::枚举成员;
```

注意因为枚举成员不再暴露到外层作用域，所以这里必须使用 `枚举类型::` 来访问枚举成员。

例如：

```cpp
// 有作用域枚举
enum class Color {
    kRed,
    kGreen,
    kBlue
};

// 另一个有作用域枚举，枚举名可以与上面相同，不会冲突
enum class TrafficLight {
    kRed,    // 与 Color::kRed 不冲突
    kYellow,
    kGreen
};

int main() {
    Color c = Color::kRed;   // ✅ 必须使用作用域限定符
    // Color c2 = kRed;      // ❌ 错误：kRed 不在当前作用域中
    
    // int value = Color::kRed;  // ❌ 错误：不能隐式转换为整型
    int value = static_cast<int>(Color::kRed);  // ✅ 必须显式转换
    
    // 比较不同类型的枚举
    // if (c == TrafficLight::kRed) {}  // ❌ 编译错误，不同类型无法比较
    
    if (c == Color::kGreen) {  // ✅ 同类型枚举可以比较
        std::cout << "绿色\n";
    }
    
    return 0;
}
```

因为有作用域枚举的枚举值**不存在**隐式类型转换，所以这里必须显式转换，将 `表达式` 的类型显式转换为 `目标类型` 的语法：

```cpp
static_cast<目标类型>(表达式)
```

例如：

```cpp
int int_num = 8;
double double_num = static_cast<double>(int_num);
```
