# 综合练习：跨文件共享配置系统

> 本次练习综合了本章所学的：构建过程、链接属性、`extern`、`inline` 等知识点。


## 一、题目背景

你正在开发一个游戏引擎，需要创建一个**全局配置系统**，让多个模块都能访问相同的配置信息（如游戏版本、最大帧率、窗口标题等）。

你需要将配置信息拆分到多个文件中，并正确使用链接属性来实现跨文件共享。


## 二、文件结构

```text
my_game/
├── config.h          # 配置声明
├── config.cpp        # 配置定义（extern 方式）
├── main.cpp          # 主程序入口
├── player.cpp        # 玩家模块
├── player.h
├── renderer.cpp      # 渲染模块
└── renderer.h
```


## 三、题目要求

### 第 1 问：头文件中的常量（内部链接）

在 `config.h` 中定义以下**编译期常量**（使用 `constexpr`），这些常量会被所有文件共享：

| 常量名            | 值           | 说明    |
| :------------- | :---------- | :---- |
| `kMaxPlayers`  | 4           | 最大玩家数 |
| `kDefaultFps`  | 60          | 默认帧率  |
| `kWindowTitle` | `"My Game"` | 窗口标题  |

**要求**：直接在头文件中定义即可（`constexpr` 默认内部链接，安全）。

>[!TIP] **提示**：`kWindowTitle` 的类型
>这里的 `kWindowTitle` 的类型可以是 `const char[]` 或 `const char*`，例如：
>
>```cpp
>constexpr const char kWindowTitle[] = "My Game"; // 窗口标题
>constexpr const char* kWindowTitle = "My Game"; // 窗口标题
>```
>
>之所以不用 `string` ，是因为目前 MSVC 编译器在 C++20 标准下可能还不支持 `string` 为字面类型。而 `constexpr` 说明的类型需要为字面类型。

### 第 2 问：头文件中的共享变量（extern 声明 + 外部链接）

在 `config.h` 中**声明**以下外部链接变量（使用 `extern`）：

| 变量名 | 类型 | 初始值 | 说明 |
| :--- | :--- | :--- | :--- |
| `g_game_version` | `int` | `1` | 游戏版本号 |
| `g_max_fps` | `int` | `60` | 最大帧率 |
| `g_window_width` | `int` | `1280` | 窗口宽度 |
| `g_window_height` | `int` | `720` | 窗口高度 |

在 `config.cpp` 中**定义**这些变量（分配内存）。

### 第 3 问：头文件中的共享变量（inline 方式，C++17）

在 `config.h` 中，用 `inline` 方式定义以下变量（C++17 现代写法）：

| 变量名 | 类型 | 初始值 | 说明 |
| :--- | :--- | :--- | :--- |
| `g_volume` | `double` | `1.0` | 全局音量 |
| `g_is_fullscreen` | `bool` | `false` | 是否全屏 |

**要求**：直接使用 `inline` 定义，不依赖 `config.cpp`。

### 第 4 问：使用配置（跨文件共享）

1. 在 `player.cpp` 中：
   - 包含 `config.h`
   - 在 `void PlayerInit()` 函数中打印 `kMaxPlayers` 和 `g_game_version`

2. 在 `renderer.cpp` 中：
   - 包含 `config.h`
   - 在 `void RendererInit()` 函数中打印 `g_window_width`、`g_window_height` 和 `g_is_fullscreen`

3. 在 `main.cpp` 中：
   - 包含 `config.h`
   - 调用 `PlayerInit()` 和 `RendererInit()`
   - 修改 `g_game_version = 2` 和 `g_volume = 0.5`
   - 再次打印所有配置信息，验证修改生效

### 第 5 问：思考题（不要求写代码）

1. `constexpr int kMaxPlayers = 4;` 在头文件中定义，为什么多个 `.cpp` 包含不会报重复定义错误？

2. `extern int g_game_version;` 和 `inline int g_volume = 1.0;` 在链接行为上有什么本质区别？

3. 如果 `config.h` 中写 `int g_game_version = 1;`（不加 `extern`），会发生什么？为什么？

## 四、参考答案

### config.h

```cpp
#pragma once

#include <string>
using namespace std;

// ===== 第 1 问：constexpr 常量（内部链接，安全） =====
constexpr int kMaxPlayers = 4;
constexpr int kDefaultFps = 60;
constexpr const char* kWindowTitle = "My Game";

// ===== 第 2 问：extern 声明（外部链接） =====
extern int g_game_version;
extern int g_max_fps;
extern int g_window_width;
extern int g_window_height;

// ===== 第 3 问：inline 变量（C++17，外部链接，可合并） =====
inline double g_volume = 1.0;
inline bool g_is_fullscreen = false;
```

### config.cpp

```cpp
#include "config.h"

// ===== 第 2 问：extern 变量的定义 =====
int g_game_version = 1;
int g_max_fps = 60;
int g_window_width = 1280;
int g_window_height = 720;
```

```cpp

void PlayerInit();
```

### player.cpp

```cpp
#include "player.h"

#include <iostream>

void PlayerInit() {
    std::cout << "[Player] 最大玩家数: " << kMaxPlayers << std::endl;
    std::cout << "[Player] 游戏版本: " << g_game_version << std::endl;
}
```

### renderer.h

```cpp

void RendererInit();
```

### renderer.cpp

```cpp
#include "renderer.h"

    std::cout << "[Renderer] 全屏模式: " 
              << (g_is_fullscreen ? "开启" : "关闭") << std::endl;

```

### main.cpp

```cpp
#include "config.h"
#include "player.h"
#include "renderer.h"
#include <iostream>

int main() {
    std::cout << "=== 第 4 问：初次启动 ===" << std::endl;
    std::cout << "标题: " << kWindowTitle << std::endl;
    std::cout << "音量: " << g_volume << std::endl;

    PlayerInit();
    RendererInit();

    // ===== 修改配置 =====
    std::cout << "\n=== 修改配置 ===" << std::endl;
    g_game_version = 2;
    g_volume = 0.5;
    g_is_fullscreen = true;

    std::cout << "版本: " << g_game_version << std::endl;
    std::cout << "音量: " << g_volume << std::endl;
    std::cout << "全屏: " << (g_is_fullscreen ? "开启" : "关闭") << std::endl;

    return 0;
}
```

## 五、思考题参考答案

**问题 1**：`constexpr int kMaxPlayers = 4;` 在头文件中定义，为什么多个 `.cpp` 包含不会报重复定义错误？

> `constexpr` 常量默认具有**内部链接**（Internal Linkage）。每个包含该头文件的 `.cpp` 文件都会得到自己独立的 `kMaxPlayers` 副本，它们互不干扰，链接器不会看到多个定义，因此不会报错。

**问题 2**：`extern int g_game_version;` 和 `inline int g_volume = 1.0;` 在链接行为上有什么本质区别？

> `extern` 方式只在头文件中声明，不会产生任何符号。唯一的定义在 `config.cpp` 中，所以所有文件共享同一份内存。`inline` 方式则让每个包含头文件的 `.cpp` 都有一份定义，但链接器会发现它们是同一个实体，自动合并为一份，不会报重复定义错误。

**问题 3**：如果 `config.h` 中写 `int g_game_version = 1;`（不加 `extern`），会发生什么？

> 这会在头文件中**定义**（而非声明）一个外部链接的全局变量。当多个 `.cpp` 包含 `config.h` 时，每个 `.cpp` 都会产生一份定义，链接器会发现 `g_game_version` 被定义了多次，报“重复定义”的链接错误。
